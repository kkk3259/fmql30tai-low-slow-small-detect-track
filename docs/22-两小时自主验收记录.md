**判读**：只检出 2~4 px，5 px 以上全丢 —— 这正是 SE=5（5×5 结构元）的行为，说明 A 的构建用的是我们**较早的快照**（SE=5、K=4、MAX_AREA=200），不是 SE=21 版。
**结论**：这不是合并引入的错误，而是快照版本差异；合并本身逐位保住了 IP2 的行为（坐标/面积/峰值全对）。

### 1.4 重要的地址差异
A 的构建是 6 位 s_axi 地址：`0x40` 会绕回 `0x00`（读 `0x40` 得到 `0x00` 的内容），所以
452 字节候选窗口（0x40/0x44）在他版里不存在，只能用 `0x18` 起的 36 字节兼容视图（n + 前 5 个候选）。
→ 已在 `ps/cand_read.py` / `ps/size_sweep.py` 里做**双视图自动判定**（用 STATUS 的 n_cand 与窗口读出的 n 比对）。

## 2. NPU：地址在、初始化开始，但**把整板跑死了**

### 2.1 先确认 NPU 真的挂在 0x40000000
```
[0x40000000+0x1C] = 0x25122301     ← 不是我们的 VERSION(0x00010000)
```
→ 说明 A 的地址分配没被我们的 IP 别名占掉（对比：我们自己的 BD 里 `0x40000000` 与 `0x43C00000` 完全别名）。

### 2.2 会话初始化“成功”，然后卡住
`npu_smoke.py` 输出：
```
[I] bind abs / t3d / conv2d / greater / log / maxpool
[info] Device initialization successful, version information: ...
（此后无输出，进程不返回）
```
紧接着板子**整机失联**：以太网链路仍 `Up 1Gbps`（PHY 活着），但 `169.254.67.100` / `192.168.126.49` 都不响应，ARP 学不到 MAC
→ 判断为 **PS 侧卡死**（AXI/总线访问挂住，CPU 无法响应中断与网络），必须断电重启。

### 2.3 可能原因（待验证，按可能性排序）
1. A 用行为级空壳顶替了 21 个 EDIF 模块（`ip_patch`） —— 若某个空壳牵涉 NPU 的 DMA/中断路径，`apply()` 之后等不到完成中断就会永久阻塞；
2. User Level Shifter 未使能（青龙 MPSOC 手册：PL 中断 16~19 上电默认浮空，必须先配 bit 再使能）→ NPU 完成中断丢失；
3. AI_Mate 的 DDR 窗口（0x80000000）在合并后与我们的 HP 口争用/译码异常。

### 2.4 处置
- 不再在无人值守时重试 NPU 会话（每次都会把板子跑死，只能断电）。
- 复现前先让 A 确认：①`ip_patch` 替掉的是哪 21 个模块 ②level shifter 的使能寄存器是否在他的 BD 里 ③中断号是否仍为 16~19。
