## 二、两条"想提升灵敏度"的路，走不通的已证伪

### 2.1 PS 侧局部均值高通（❌ 反而更差）

思路：先在 PS 里做 `img - blur31(img)`，把云的慢变纹理拉平，小目标就好检。

实测（`--pre hp`，同上 8 段）：

```
平均召回 2.3%   平均精确 1.3%   候选 5.2/帧
```
比不处理（13.5%）**更差**。

原因：31×31 均值窗里也包含目标自身的能量，减掉后目标反差被削弱；而 Top-Hat 之后本来就没剩多少。

### 2.1b **gamma 曲线预处理（✅ 找到了，效果最大）**

思路：送 PL 之前先做幂律拉伸 `out = 255·(x/255)^γ`（γ<1 提亮暗部）。

机制：γ 把**背景的动态范围压扁**（云的明暗差被压到很小），CFAR 的 `mean + K·sd + floor` 里 `sd` 项随之变小，弱目标的局部反差相对就突出了。这不是"调亮度"，是改变了 CFAR 自适应门限的统计特性。

实测（同一 12 段测试集，`--inv both --border 24`）：

| γ | 平均召回 | 平均精确 | 候选/帧 |
|---|---|---|---|
| 1.0（原样） | 9.0% | 0.9% | 22.2 |
| 0.70 | 14.9% | 2.1% | 27.9 |
| 0.50 | 31.5% | 3.2% | 32.3 |
| 0.35 | 45.4% | 7.7% | 21.5 |
| 0.20 | 55.4% | 38.7% | 16.4 |
| 0.12 | 69.0% | 43.2% | 15.2 |
| 0.08 | **76.6%** | 54.9% | 10.6 |
| 0.05 | 66.2% | **73.2%** | 6.6 |

- γ=0.08 召回最高（76.6%），γ=0.05 精确最高（73.2%）且 F1 更好（0.70 vs 0.64）
- **F1 最优区间 γ≈0.05~0.08**，召回相比原样提升 **8.5 倍**，精确提升 **81 倍**

γ=0.05 的分场景表现：

| 场景 | 召回 | 精确 |
|---|---|---|
| grass_man | 97.5% | 72.4% |
| sky_bird_multi | 92.7% | 99.8% |
| sky_tiny | 92.6% | 100.0% |
| sea_plane | 92.3% | 98.4% |
| grass_car | 91.2% | 92.0% |
| sea_bird | 90.8% | 99.8% |
| sky_plane_far | 68.1% | 50.7% |
| clouds_drone | 61.0% | 67.5% |
| clouds_bird | 53.8% | 94.2% |
| sky_drone_multi | 23.8% | 96.6% |
| night_drone | 19.0% | 4.3% |
| night_bird | 12.0% | 3.0% |

**弱点仍在夜间**（强噪点把 CFAR 的 σ 抬高，目标被淹）——这是下一轮要攻的点。

代码：`--pre gamma --gamma 0.05`（评估脚本）/`--gamma 0.05`（`cam_pipe.py`、送 PL 前拉伸，显示画面不受影响）。

### 2.2 裸 Vivado 流程重编 K=0/FLOOR=2（❌ 出不了可用位流）

写了 `synth/vivado/rebuild_fast.tcl`（read_verilog + synth_design + place + route，无工程）。

两次失败：

```
ERROR: [Place 30-99] Placer failed with error: 'IO Clock Placer failed'
ERROR: [Common 17-69] Command failed: Placer could not place all instances
```

补了最小 XDC（`create_clock -period 20 [get_ports clk]` + 降级 NSTD-1/UCIO-1）仍然报同一个错。

**根因**：裸流程没有板级引脚约束，时钟端口没有落到 clock-capable pin；更根本的是——**裸 AXI 端口的位流本来就没法和 PS 对接**，我们真正能用的位流必须来自带 PS7 的 BD 工程（`ip2_ps4`）。

⇒ K/FLOOR 的敏感度实验，只能走"工程流 + 重打包 IP"，那是 25~40 分钟一轮，本轮时间不够。
