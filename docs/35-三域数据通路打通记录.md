## 2. 修好的两件事

### 2.1 寄存器连写会丢（软件侧规避）
`detect3d.detect()` 原来把 `0x04 / 0x08 / 0x00(0) / 0x00(1)` 四个写背靠背发出去，我们的 ra→core 中继用 toggle 握手，
**两笔写间隔小于 2 个 core 周期时只认到一笔**，于是 `start_req` 没置起来，整帧不启动（表现为 AR 不增长、读到上一帧的陈旧候选表）。

规避：每次写之间 `time.sleep(0.02)`，启动写后 `sleep(0.005)`。加完之后 **AR 从 7218 → 10827（+3609 = 整帧），每帧都能跑起来**。

> 根本解法在 RTL：把写中继从"toggle 边沿"改成"1 深 FIFO + 计数"，这样连写不丢。列为下一步。

### 2.2 `dbg_ar` 一直是 0 是我的 Python 写错，不是 RTL 错
```python
# 错：签名是 read(addr)，多传一个 4 会抛异常，被 catch 吞掉后返回 0
dev.defaultRegRegion().read(addr, 4)[0]
# 对：
dev.defaultRegRegion().read(addr) & 0xFFFFFFFF
```
改正后：`AR(0x90) = RV(0x94) = 3609`，**完全配平**，整帧 3600 行一行不少。

## 4. 仍然存在的问题

1. **x 整体 +35**：行内起点偏移，需要查 `px_pushed` 与行首对齐（怀疑第一行开头被丢了 35 字节，或 `o_ext_go` 早了一拍）。
2. **第二帧起 `done=0 err=1`**：帧间复位不干净 —— `feed_on / inflight / lf_cnt / adq_cnt` 没在新一帧开始时清零，导致 F_FEED 看门狗超时。候选表里混着上一帧的 (521,359) 等旧值。
3. **耗时 240 ms（首帧）/31 ms（后续）**：三域里每帧 3609 次 AR、每次等约 1024 拍（平台 DDR 延迟），比独立版的 14 ms 慢一个量级。要提速必须让 AR 流水（`inflight` 从 6 提到 16 并真正流水）。

## 6. 第二轮补充实测（03:40~04:10）

### 现象：起帧交替，一帧跑一帧不跑
`
只写 CTRL=1（不先写 0），连发三次：
帧1: AR 18045->21654 (+3609)   ← 跑
帧2: AR 21654->21654 (+0)      ← 没跑
帧3: AR 21654->25263 (+3609)   ← 跑
`
写 0 再写 1（带 20 ms 间隔）时也一样交替。
⇒ **start_req 每两帧才被消费一次**，不是每帧一次。

### 另一个坑：done 位不会自清
轮询条件写成 if (st & 1) break 时，第二帧 0 ms 就返回，
读到的是上一帧的 done=1。必须改成"等 AR 增长 + done 置位"双条件。

### 下一个要查的点
wr_req_ev 是单周期 toggle 边沿事件，start_req 由它置位；
怀疑检测器侧 start_req 被 FSM 消费后，我方又一次把它置起来（或反之），
导致每次启动需要两次 CTRL 写。**根治方案：写中继改 1 深 FIFO + 计数**（已在计划内）。

## 7. 第三轮改动（04:20~05:00）：起帧改自发延时启动

根因判断：if (o_ext_go && start_req) 这个握手会丢——检测器 F_RST 末拍的脉冲与我方 start_req 的消费不同步，表现为"每两帧才启动一次"。

改法：写 CTRL=1 就清零全帧状态（feed_on/line_idx/inflight/px_pushed/lf_wp/lf_rp/lf_cnt/lbcnt），
延时 96 个核周期（1.9 µs，远大于 F_RST 的 32 拍 + FIFO 清空窗）后无条件 eed_on<=1，彻底去掉握手依赖。

仿真回归：PUSHED=3072 请求行=61 AR=57 RV=57 WD=0、捕获 0/256 不一致、VERDICT LINE-OK。
提交 `be894f0`。位流 `ours3d_s4` 编译中。

## 9. 第五轮（05:00~05:30）：学长寄存器 0x01 的打包格式（重要发现）

`rtl/adder_op/reg_ctrl.v:130-133`：
`erilog
else if (ra_awevent && ra_awaddr == 16'h01) begin   // RSIZE_BASE
    rbase <= ra_awdata[15:0];     // 低 16 位 = PL-DDR 基址
    rsize <= ra_awdata[31:16];    // 高 16 位 = 读多少行（64 字节/行）
end
`
`dma.v` 直接拿 `arsize` 当读循环次数：`dma_cnt0 <= arsize`，`arvalid` 一直到 `arready && dma_cnt0==0` 才撤。

**含义**：平台帧控制器需要“基址 + 行数”两个信息，通过寄存器 **0x01** 告知；我们一直只写自己的 0x04，从没写过 0x01。
这可能解释：①每次 AR 等 ~1024 拍；②第 2 帧起超时。

**待验证**：往 0x01 写 `(3600<<16)|0x1000` 后行为是否变化。
（首测脚本无输出即结束，板子未挂，原因待查——可能是 0x01 在本位流里未实现，写入无响应。）
