## 1. 先确认板子状态

```bash
ssh root@<板子IP>
cat /sys/class/fpga_manager/fpga0/state        # 期望 operating
pgrep -af 'cam3d_pipe|cam_pipe'                # 看现在跑的是哪条链路
```

三种情况：

| 现象 | 说明 | 处理 |
|---|---|---|
| `operating` + `cam3d_pipe` 在跑 | 三域链路在线 | 跳到第 3 节 |
| `operating` + `cam_pipe` 在跑 | 独立检测器链路在线 | 跳到第 2 节切三域 |
| `state` 不是 operating / 没有进程 | 位流没加载或板子重启过 | 从第 2 节开始 |

## 2. 加载三域位流（重启后必做）

**顺序不能反**：先杀进程 → 等 3 秒 → 再写 firmware。进程持着 PL 时重配会把 PS 总线挂死（要断电）。

```bash
# 1) 停服务、杀干净
/etc/init.d/ip2d3 stop 2>/dev/null
/etc/init.d/ip2demo stop 2>/dev/null
pkill -9 -f 'cam3d_pipe'
pkill -9 -f 'cam_pipe'
sleep 3

# 2) 确认真没人了（这条必须为空）
pgrep -af 'cam3d_pipe|cam_pipe'

# 3) 加载三域位流
echo ours3d_s5.bin > /sys/class/fpga_manager/fpga0/firmware
sleep 3
cat /sys/class/fpga_manager/fpga0/state          # 期望 operating

# 4) 探活：只读一次 VERSION，必须回 0x00010000
python3 -c "
from icraft.xrt import Device
d=Device.Open('axi://zg330aiu?npu=0x40000000&dma=0x80000000')
print('VERSION = 0x%08X' % (d.defaultRegRegion().read(0x400C0014)&0xFFFFFFFF))
"
```

如果第 4 步报错或卡住 → **立刻停手**，板子可能要断电重启（见第 6 节）。

> 位流文件清单（都在 `/lib/firmware/`）：`ours3d_s5.bin`（三域，最新）、`se31.bin`（独立版 SE=31）、`ip2_k0.bin`（独立版 K=0）。

### 三种启动参数，各试一遍并截图

```bash
# A. 默认（彩色画面，不做 gamma）
/etc/init.d/ip2d3 stop; sleep 2
python3 cam3d_pipe.py --port 8080 --gamma 1.0 --color 1

# B. gamma 0.08（背景抬亮、动态范围压缩 → CFAR 的 sd 变小 → 弱目标更容易过门限）
/etc/init.d/ip2d3 stop; sleep 2
python3 cam3d_pipe.py --port 8080 --gamma 0.08 --color 1

# C. 逆光天空场景（找暗目标：鸟 / 无人机）
/etc/init.d/ip2d3 stop; sleep 2
python3 cam3d_pipe.py --port 8080 --gamma 0.08 --invert 1 --color 1
```

> 注意：`--invert 1` 是“把 255−gray 送进 PL”，等价于 Black-Hat（找暗目标）。检测是在灰度上做的，画面显示不受影响。
> gamma 只改“送进 PL 的那份”，**显示的还是原图**，所以画面亮暗不变、只有框的数量会变。

## 7. 已知问题（不用你修，我这边在弄）

1. **检测窗口只有 2~4 px**：三域位流的检测器是 `.SE(5)`，为了压资源（SE=21 时 LUT 114% 装不下）。比赛目标 15~70 px 检不到。
2. **画面偏灰**：三域版之前直接推灰度原图（独立版推彩色 + gamma）。第 4 节的改动就是修这个。
3. **NPU 判"非无人机"**：cls128 是二分类模型，对显示器靶图本来就不认；只有对真实无人机目标才有意义。
4. **三域里 SE 最多只能到 9**（LUT 95.8%），要更大就得砍平台（放弃 NPU）。
