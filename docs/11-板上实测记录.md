### 1.2 踩过的坑：卡容量不足

首次误用 32GB 卡（实测 31,075,107,840 字节 = 28.94 GiB）烧写，imageUSB 日志：

```
Warning: Destination Drive (31077695488 bytes) is smaller than the image file (31914983424 bytes).
Continuing on Drive ... No drive verification will be performed
Wrote past the end of the drive
```

**结论：镜像需要 ≥ 29.72 GiB 的卡，32GB 卡（标称）实际只有 28.94 GiB，差 837 MB 装不下。**
**⇒ 必须用 64GB 卡。** 该 32GB 卡分区表已被写坏，需 `diskpart clean` 后才能复用。

### 1.3 启动配置（手册 4.2）

板上有 4 组 3 针跳线帽（`J1`~`J4`），对应 `MIO2`/`MIO3`/`MIO4`/`MIO5`。
每组 3 针从上到下为 `VCC3V3` / 信号 / `GND`，跳线帽骑「上+中」= 1，「中+下」= 0。

| 跳线 | 信号 | SD 卡启动设定 |
|---|---|---|
| **J4** | MIO5 | **1**（上+中）|
| **J3** | MIO4 | **1**（上+中）|
| **J2** | MIO3 | **0**（中+下）|
| **J1** | MIO2 | **0**（中+下，级联模式）|

启动模式表（手册 4.2）：

| BOOT MODE | MIO5 | MIO4 | MIO3 |
|---|---|---|---|
| JTAG | 0 | 0 | 0 |
| QSPI | 1 | 0 | 0 |
| **SD CARD** | **1** | **1** | **0** |

`MIO6` = 0 → PLL Enabled；`MIO7`/`MIO8` = 1/1 → 1.8V（SD 卡要求 BANK501 = 1.8V）。
**这三个不是跳线帽，是固定电阻上下拉，出厂已配好，不需要动。**

## 三、NPU 摸底（2026-10-22 过程记录｜⚠️ 结论已于 2026-10-23 推翻）

> ⚠️ **本章的结论「硬件通路不通」是错误的，保留原文仅作过程记录。**
> **2026-10-23 晚的实测证明：AI_Mate 一直在位流里、PS 能正常访问（`Device initialization successful`，读出版本号 `25122301`）。**
> **真实根因是三条判断失误叠加：① 扫错了 AXI 地址（`0x400C0000` 是 custom op 区，AI_Mate 在 `0x40000000`）；② 装错 Icraft 版本（3.36.0 与官方 demo 程序的 3.33.1 符号不兼容）；③ 用 `icraft-run` 命令行拼参数，而官方走 C++ `Device::Open()`。**
> **⇒ 完整的打通过程见 [第十章](#十npu-打通全过程2026-10-23)。**

### 3.0 原文（2026-10-22，结论已作废）

|---|---|

| `--input` | **图片**或 ftmp 文件（required）|
| `--backends` | 后端列表，用 `;` 分隔多个后端，用 `,` 分隔后端名与设备描述 |
| `--log_time` / `--log_io` | 打印耗时 / 输入输出信息 |

| `--close_mmu` | 关闭 MMU |

官方配置里的后端写法示例：

```yaml
device: axi://zg330aiu?npu=0x40000000&dma=0x80000000     # 本地 AXI 直连
--backends ZG330,socket://haps-zg330@192.168.124.24:5001;Host   # 远程 socket
```

### 3.4 三种后端组合的实测结果

| 后端写法 | 报错 | 含义 |
|---|---|---|
| `Host` | `Op is NOT bound to any backend, op_id = 671, type_key = HardOpNode` | **CPU 后端绑不了硬件算子**（模型里全是 HardOp）|
| `ZG330` | `Op is NOT bound to any backend, op_id = 0, type_key = InputNode` | **ZG330 后端成功绑定了 HardOp**，但 Input 节点需 CPU 后端 |
| `ZG330;Host` | **Segmentation fault（exit 139）** | **绑定全过，`apply()` 阶段访问 AXI 地址时崩** |
| `ZG330,socket://localhost:9981;Host` | `libsocketlocalhost.so does not exist` / `libsocketzg330.so does not exist` | **socket 语法需 `socket://<库名>@<host>:<port>`，库名对应 `libsocket<名字>.so`（板上是 `libsocketzg330aiu.so`）** |

**⭐ 关键进展信号**：`ZG330` 能创建出来、能绑定 HardOp（不再抱怨 671），说明**软件栈是通的**，问题在硬件访问。

### 3.5 ⭐ 硬件通路的决定性诊断

**（1）AXI 地址扫描：64 KB 内零响应**

```python
# 读 /dev/mem，从 0x40000000 起每 4 KB 取首字
0x40000000 -> 0x00000000
有响应的地址数: 0
```

**⇒ PL 的 AXI 地址空间里，没有任何从设备在应答。**

**（2）`/proc/iomem` 布局**

```
00000000-3fffffff : System RAM          ← 1 GB DDR 全归内核
  2fded000-3fffffff : reserved          ← 258 MB 被保留（用途未知）
e0000000-e0000fff : e0000000.spi
e0003000          : gpio 系列
e0004000          : serial
e0040000          : devcfg             ← PL 配置管理器（/dev/fpga0）
e0043000          : dwmmc
e0045000          : usb
e0047000          : ethernet
e004b000          : dma
```

**⚠️ `0x40000000`（npu）和 `0x80000000`（dma）在 `/proc/iomem` 里完全没有出现** —— 既不是 System RAM，也不是已注册外设，是**未被映射的空白区**。

**（3）DMA 区被内核当普通内存**

```
0x80000000 -> 0xBAAAAAAA     ← Linux 内核的 0xAA poison 填充标记
```

**⇒ 那块物理内存被内核当普通 RAM 管理了，没有用 `reserved-memory` / `no-map` 保留。**

**（4）设备树极简**

```
find /proc/device-tree -maxdepth 2   →   只有 /proc/device-tree 根
```

**⇒ 没有 `reserved-memory`、没有 `npu`、没有 `zg` 节点。**

### 3.6 ⇒ 结论（⚠️ 已被 2026-10-23 实测推翻）

> **下表有两行是错的，2026-10-23 晚已证伪：**
> - 「位流含 ZG330 AXI 从设备：❌ 没有」→ **实际有**，`0x40000000 + 0x1C` 读出 AI-Mate 版本号 `0x25122301`
> - 「设备树保留 NPU/DMA 地址：❌ 没有」→ **实际有**，`dma=0x80000000` / `npu=0x40000000` 均可用，官方 demo 打开设备成功
>
> **失败的真实原因不是「缺位流/缺设备树」，而是「扫错地址（`0x400C0000` 是 custom op 区）+ 装错 Icraft 版本（3.36.0）+ 用错调用方式（`icraft-run` 命令行）」，见第十章。**

### 3.8 `uEnv.txt` 揭示的启动机制

```bash
bootcmd = run loadbit; run uenvcmd

# PL 位流从【第 2 个分区】加载，文件名必须是 download.bit
loadbit = mmc rescan && fatload mmc 0:2 0x10000000 download.bit && fpga loadb 0 0x10000000 $filesize

# 内核从【第 1 个分区】加载
uenvcmd = mmc rescan && fatload mmc 0:1 0x10080000 Image && fatload mmc 0:1 0x11000000 fmqlmp-verify.dtb && booti 0x10080000 - 0x11000000
```

**⚠️ 注意**：`loadbit` 要从 `mmc 0:2`（第 2 分区）fatload，但我们的 p2 是 ext4 根文件系统 —— **所以这条 `loadbit` 实际不生效**。

**⇒ 位流实际是由 `BOOT.bin` 内嵌、FSBL 启动时自动加载的**（`fpga0 = operating` 证明了这一点）。

**⚠️ 将来若要换位流，最稳的方式是重新打包 `BOOT.bin`（FSBL + 新位流），或把新位流改名 `download.bit` 放进 p1 并改 `uEnv.txt` 的 `mmc 0:2` → `mmc 0:1`。**

### 5.1 耗时构成（真实 630 帧）

### 5.2 两个瓶颈与对应加速手段

### 7.8 ⭐ `qinglong_guide.txt` 里的三条关键机制（对 P 极其重要）

**机制一：User Level Shifter（电平转换总开关）**

> PS 与 PL 之间的电平隔离/安全开关。**上电后默认关闭**，需要在「配置好 PL 位流之后」手动使能。
> **使用铁律：没有配置 bit，不能使能 User Level Shifter。**
> 原因：PL 中有 4 根中断直通线（16~19 号中断）连到 CPU 的 FIQ/IRQ。没有 bit 时这 4 根线是浮空的。
> **正确顺序：先下载/配置 bit → 再使能 Level Shifter → 再访问 PL 资源。**
> **QSPI/SD 自主启动时：FSBL、u-boot、Linux 会自动判断并自动使能，无需用户处理。**

**机制二：HP 接口的「重新使能（HP Re-enable）」**

> HP（S_AXI_HP）是 PL 主动高带宽访问 PS DDR 的接口，共 4 路，只支持 64bit、只能访问 DDR（不能访问 OCM）。
> FSBL 的 `ps_init` 会根据 BD 里是否勾选 HP 去使能它（第 1 次），但此时 bit 还没加载。
> **FSBL 配置完 bit 之后，需要再使能一次 HP** —— 这就是「HP Re-enable」。
> **HP 其它约束**：不支持 burst 跨 4KB 边界；GP/HP 接口设计最大频率 100 MHz（要更高必须打最新 IP patch）。
> **HP 大数据量要加 FIFO**（复旦微 DDR 控制器没有 Xilinx 那样的硬件 FIFO）。

**机制三：JTAG 级联 vs 独立**

> **级联（MIO2 = 0）**：PS 与 PL 在同一条 JTAG 链上，J-Link 接 PL-JTAG 可同时访问两者。**入门实验都用级联。**
> **独立（MIO2 = 1）**：链被断开，PL-JTAG 只能单独访问 PL。存在的主要意义是**用 ILA 抓 PL 内部信号**。
> **调试器分工**：PL 用 PL JTAG 下载线（Xilinx 兼容 cable），PS 用 J-Link，**不支持同一个仿真器同时联调**。

**⇒ 我们设 `MIO2 = 0`（级联）是正确的。**

**机制补充（2.6 Vivado PL 补丁）**

> **IP patch（IP 补丁）**：在 Vivado 工程上执行，替换部分 IP/时序库。**补丁包和操作手册在下载站，全系列通用。**
> **bit patch（位流补丁）**：**已集成在 Procise 的 Tools 菜单中**，对 Vivado 生成的 bit 进行处理。
> **新手第一遍做纯 PS 实验时可暂不涉及补丁；一旦要正式开发 PL，务必按下载站补丁手册操作。**

## 十、NPU 打通全过程（2026-10-23）

> 本章取代第三章的旧结论。所有结论均有板上实测输出或官方源码原文支撑。

### 10.1 结论先行

| 环节 | 状态 | 证据 |
|---|---|---|
| 位流含 AI_Mate | **✅ 有** | `0x40000000+0x1C` = `0x25122301`（AI-Mate 版本号）|
| PS 能访问 NPU | **✅ 能** | `Device initialization successful` |
| PL DDR3 初始化 | **✅ 成功** | `PL_LED1/J1` 闪烁（`ddr3_init_done & ddr_clk_led`）|
| 设备树支持 | **✅ 支持** | 官方 demo 直接 `Device::Open()` 成功 |
| 模型部署（apply） | **⚠️ 版本错位** | 程序 3.33.1 vs 模型 3.36.0 → `icraft::InternalError` |

**⇒ NPU 不再是「能不能用」的问题，而是「版本对齐」的收尾工作。**

### 10.2 三条判断失误（2026-10-22 的错误结论从何而来）

| # | 我们做的 | 正确的 | 后果 |
|---|---|---|---|
| **1** | 扫 `0x400C0000`（FPAI_DEMO 说的 custom op 区）| AI_Mate 寄存器在 **`0x40000000`** | 读回全 `0xFFFFFFFF`，误判「没有从设备」|
| **2** | 装 Icraft **3.36.0**（以为越新越好）| 官方 demo 程序是 **3.33.1** 编的 | `symbol lookup error: Network::lazyLoadParamsFromFile(std::string,bool)` |
| **3** | 用 `icraft-run` 命令行拼 `--backends` | 官方用 C++ `Device::Open()` + yaml `run_backend: zg330` | `Host` 后端在 aarch64 段错误 |

**⇒ 三个错误叠加，绕了整整一天。教训：官方 demo 包里的版本号是配套的，不要擅自「升级」。**

### 10.3 ⭐ AXI 扫描：AI_Mate 寄存器窗口（决定性证据）

**位流：`BIT.rar / 30tai_lite_detpost / BOOT.bin`（2026-09-14，md5 `c3cab5a74d0ee2774d03e6aefcce93b6`）**

```
0x4000001C -> 0x25122301     ★ AI-Mate 版本号（官方 README 标注 AI Mate 版本 25122301）
0x40000030 -> 0x00000010
0x40000040 -> 0x7F000000
0x40000048 -> 0x3F000000
0x400000E0 -> 0x00000001
0x400000E4 起 -> 0xFFFFFFFF   超出寄存器窗口（DECERR）
```

**⇒ 寄存器窗口仅约 224 字节（`0x40000000~0x400000E3`）。`0x400C0000` 完全在窗口外，所以那里读全 F 是**正常**的。**

### 10.4 ⭐ PL_LED1（J1 / D18）= DDR3 初始化指示灯（官方 RTL 原文）

```verilog
// rtl/ps_ai_peripheral.sv
1832 | .init_calib_complete (ddr3_init_done)      // MIG → ddr3_init_done
1506 | .ddr3_init_done       (ddr3_init_done)      // → AI_Mate 的 input 端口
 664 | assign led[0] = ddr3_init_done & ddr_clk_led;

// rtl/utils/demo_clkrst_wrapper.v
always @(posedge ddr_clk) led_cnt <= led_cnt + 1;
assign ddr_clk_led = led_cnt[26];                 // 2^26 分频的「心搏」信号
```

**⇒ `led[0]`（PL_LED1 / J1 / 丝印 D18）闪烁 = DDR3 初始化成功 + DDR 时钟正常。**

**⇒ 这是一颗官方埋好的硬件自检点，无需任何软件即可判断 PL 状态。**

### 10.9 板卡按键与 LED（手册 4.11 / 4.12 + 实物图）

| 信号 | 引脚 | 作用 |
|---|---|---|
| **复位按键** | 不占 FPGA 引脚 | **硬复位整个系统（替代拔电重启）** |
| `PS_KEY` | **B19**（PS_MIO47）| PS 侧按键，Linux 可读 |
| `PL_KEY1` | **F8** | **官方设计里接 `sys_rst`（PL 复位，高有效，`assign sys_rst_n = ~sys_rst`）** |
| `PL_KEY2` | **E7** | 官方设计里接 `rx_gtx_full_reset`（SDI GTX 复位）|

| LED | 引脚 | 位号 | 含义 |
|---|---|---|---|
| **PL_LED1** | **J1** | **D18** | **`ddr3_init_done & ddr_clk_led`** ← DDR3 自检 |
| PL_LED2 | M6 | D20 | `led3`（外部输入）|
| PL_LED3 | H7 | D19 | 本设计未赋值 |
| PL_LED4 | J8 | D21 | 本设计未赋值 |
| PS_LED | E23（MIO7）| D4 | PS 侧 |

**⚠️ 手册写「4 个按键」，实物有 6 个 —— 手册与实物不一致，以丝印为准。**

**⚠️ `sys_rst`（F8）的 xdc 里没有 `PULLUP/PULLDOWN` 约束，若按键卡住会导致 PL 一直复位 → MIG 不初始化 → D18 不亮。**
