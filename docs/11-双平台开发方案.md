# 11 - 双平台开发方案（FMQL45T900 → FMQL30TAI）

> **2026-10-14 确认**：指导老师提供 **FMQL45T900** 核心板，经官方同意"可以先用这个搞"；
> **最终参赛平台仍为 FMQL30TAI（悟净）**。本文说明两平台的差异、必须遵守的纪律，以及分工。

---

## 一、两平台硬件差异（来源：复旦微官网参数页）

| 项 | **FMQL45T900**（现在开发用）| **FMQL30TAI**（最终参赛用）|
|---|---|---|
| 产品线 | FMQL 系列 PSoC | FPAI 异构智算系列 |
| 架构 | **CPU + FPGA** | **CPU + NPU + FPGA** |
| **NPU** | ❌ **无** | ✅ **ZG330，8 TOPS@INT8** |
| 逻辑资源 | 350K | **125K** |
| LUT | 218,600 | **78,600** |
| BRAM | 19.2 Mb | **9.3 Mb** |
| DSP | 900 | **400** |
| PS 主频 | 800 MHz | 1 GHz |
| PS 二级缓存 | 256 KB | 1 MB |
| 高速接口 | 16 路（PCIe Gen2 x8）| 4 路（PCIe Gen2 x4）|
| 封装 | **FCFBGA900**（31×31mm）| **FCBGA676**（27×27mm）|
| 典型功耗 | 较高 | ~8 W |
| 开发工具 | **Vivado**（兼容 Zynq-7045）/ FMSH 工具链 | **Procise + Icraft** |
| 片上接口 | 2×AXI_GP Master、2×AXI_GP Slave、**4×AXI_HP Slave** | 同类 |

> **核心板丝印**：`TES745D_V10` / "复旦微 FMQL45T900 核心模块"
> **判定依据**：官网 45T900 参数页中 `NPU`、`TOPS`、`iCore`、`ZG330` **零出现**；30TAI 页面有独立的"NPU AI 加速引擎"参数栏。

## 二、三条纪律（**必须遵守，否则迁移会翻车**）

### 纪律 1 ⭐：资源预算按 30TAI 卡死

```
LC   ≤ 125K
DSP  ≤ 400
BRAM ≤ 9.3 Mb
```

**原因**：45T900 的资源是 30TAI 的 **2.8 倍** —— 如果按 45T900 自由使用，
会出现"**在 45T900 上能跑、搬到 30TAI 放不下**"。

**做法**：**每次综合后运行**

```powershell
D:\lowslow\venv\Scripts\python.exe tools\check_budget.py --report <综合报告.rpt>
# 或手动粘数字
D:\lowslow\venv\Scripts\python.exe tools\check_budget.py --lc 45210 --lut 28100 --dsp 120 --bram 3.2
```

输出会给出"**占 30TAI 的百分比**"，**超过 100% 必须优化**。

### 纪律 2：接口契约不变

`docs/01-接口与协作规范` 定义的 **I1~I5** 字段、坐标约定、字节数 —— **一律不动**。

**迁移时只换实现，不动接口** → 上层代码零修改。

### 纪律 3：判别环节"后端化"

`ps/ps_app.py` 的 `RoIJudge` 支持三种后端，用环境变量 `ROIJUDGE_BACKEND` 控制（默认 `auto` 自动探测）：

| 后端 | 适用平台 | 行为 |
|---|---|---|
| **`npu`** | 30TAI | 走 Icraft 推理（`_npu_infer`，**当前为未实现占位**）|
| **`cpu`** | 45T900 / PC | 走 ONNX Runtime（`_cpu_infer`，**无模型时返回 1.0**）|
| **`placeholder`** | 任意 | 直接返回 1.0（全部通过）|

**用法**：
```powershell
$env:ROIJUDGE_BACKEND = "cpu"      # 或 npu / placeholder / auto
python ps\ps_app.py --src 视频.mp4 --model D:\models\roi_cnn.onnx
```

**已实测的边界行为**：
- 在无 NPU 的平台上强制 `npu` → **优雅回退占位并打印提示**（不崩溃）
- `--no-classify` → **完全跳过判别**（不经后端分派）
- 无模型 → 占位通过，**链路不中断**

## 三、为什么这样设计能"保证迁移"

| 资产 | 能否迁移到 30TAI | 依据 |
|---|---|---|
| **RTL 逻辑**（`pl/rtl/` 10 个 `.v`）| ✅ **完全能** | 纯 Verilog，无厂商原语依赖；两边都是"对标 Zynq"的 PS+PL 架构 |
| **PS↔PL 的 AXI 通路** | ✅ 能（改地址映射）| 两边都有 AXI_GP / AXI_HP（45T900 官网明列：2×GP Master、2×GP Slave、4×HP Slave）|
| **I1~I5 接口定义** | ✅ **不变** | 字段级契约，与芯片无关 |
| **软件链**（`baseline/`、`ps/`）| ✅ 大部分能 | 纯 Python/OpenCV，只改 ★替换点 |
| **约束文件** | ❌ **必须重写** | 封装不同（FCFBGA900 vs FCBGA676），引脚不通用 |
| **NPU 相关** | ❌ 45T900 做不了 | 需在 30TAI 上补 |

**→ 除了"约束"和"NPU 实现"，其余全部可迁移。**

## 六、⭐ 一个附加好处

在 45T900 上用 **CPU 跑模型**，正好能产出"**CPU 推理 vs FPGA 加速**"的对比数据 ——

而赛题原文要求：**"应给出软件实现与 FPGA 实现的性能对比，包括吞吐率、延迟、资源占用、功耗估计或系统帧率"**

**→ 我们的"临时方案"反而成了加分素材。**
