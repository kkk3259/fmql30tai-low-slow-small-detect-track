## 二、三个"AI 出错并被人工发现修正"的真实实例（答辩重点）

### 实例 1：视频输出尺寸不匹配（09-29）
- **AI 生成的问题**：三画面拼接后尺寸为 1920×360，但视频写入器声明的是 1280×720
- **现象**：控制台刷屏 `write FFmpeg: Failed to write frame`，输出 mp4 只有 0 KB
- **定位**：做对照实验（同尺寸正确、不匹配错误）→ 实测"声明 1280×720 写 1920×360"只写入 **257 字节**（文件头），证明尺寸不一致会静默失败
- **修正**：把写入器尺寸改为动态取面板尺寸，并加 `assert panel.shape == (H_OUT, W_OUT)` 断言
- **修正后**：`results/baseline_synth.mp4` 3.9 MB / 150 帧，播放正常

### 实例 2：快捷方式参数被截断（09-30）
- **AI 生成的问题**：用 `-EncodedCommand`（Base64）把长命令塞进桌面快捷方式参数
- **现象**：双击"低小慢-项目命令行"窗口一闪而过，看似"打不开"
- **定位**：读回 `.lnk` 里**实际存储**的参数 → 长度恰好 **1023**（Windows 快捷方式命令行上限），Base64 串尾断在半截；PowerShell 报 `value specified with -EncodedCommand is not properly encoded`
- **（附带教训）**：第一次"验证通过"是假通过——执行的是内存变量而非 `.lnk` 里的参数
- **修正**：精简命令使参数降到 **740 / 732 字符**，并改用"读回 `.lnk` 实际参数执行"的验证方式；退出码 0，输出正常

### 实例 3：合成测试序列过于"干净"（09-30）
- **AI 生成的问题**：合成序列的背景起伏 σ 只有 0.49 灰阶（几乎无杂波）
- **现象**：Top-Hat 增强前后几乎无差别，指标提升 **-0.36 dB**（负值！），无法体现算法价值
- **定位**：分析发现局部背景统计窗口内既无云团也无强噪声，Top-Hat "无东西可压"
- **修正**：合成背景加入 14 个低频云团（幅度可达 ±40 灰阶）
- **修正后**：背景起伏 σ 达 **9.22**，目标可检测性从 **-1.40 dB 提升到 +20.26 dB（+21.66 dB）**，效果显著
