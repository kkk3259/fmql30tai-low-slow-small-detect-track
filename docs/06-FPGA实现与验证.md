## 1 PL 在系统中的角色

本系统采用三层异构架构：**PS** 做采集/调度/跟踪（控制面），**PL** 做像素级数据面运算，**NPU** 做 ROI 精判别。

PL（FPGA）承担链路中**数据量大、逻辑规则固定**的三段像素级运算：

```
彩色帧 ──▶ [IP1 预处理] ──▶ [IP2 增强+检测] ──▶ [IP3 后处理] ──▶ 候选列表 ──▶ NPU/PS
          灰度+降采样      Top-Hat→CFAR→CCL      ×2+NMS
```

## 2 模块划分与实现

| IP | 文件 | 功能 | 关键实现 |
|---|---|---|---|
| **IP1** | `preproc_axis.v` | 彩色(BGR)→灰度 + 2×降采样 | 14 位定点 BT.601，**无高斯**（见 D1） |
| **IP2-①** | `tophat_5x5.v` | 5×5 形态学 Top-Hat | 纯 min/max 比较，无乘法 |
| **IP2-②** | `cfar_threshold_stream.v`（流式）／`cfar_threshold.v`（旧全帧） | 31×31 自适应阈值 | **真实 std + 滑动盒 O(1)**：流式版用行/列和 + 环形线 + 平方流，判决走平方比较 |
| **IP2-③** | `candidate_extract.v` | 连通域标记(CCL) + 候选提取 | 8 连通 BFS 洪泛 + 质心/面积/峰值 |
| **IP2 顶** | `ip2_top.v` | 三段串联整合 | Top-Hat → CFAR → CCL |
| **IP3** | `postproc_axis.v` | 非极大值抑制(NMS) | 合并过近候选（矩形邻域），输出降采样坐标 |
| **IP4** | `roi_pack.v` | 裁 ROI 打包 | 按候选裁 128×128 ROI（越界补 0），I3 接口 |

### 2.1 IP1 预处理：14 位定点灰度化（0 误差）

灰度化对齐 OpenCV BT.601，用 14 位定点避免 8 位系数截断误差：

```
gray = (4899·R + 9617·G + 1868·B + 8192) >> 14
```

8 位系数版（`(77R+150G+29B)>>8`）与 OpenCV 存在 **28/256 像素的 1 LSB 误差**；
改用 14 位精确系数后，**与 `cv2.cvtColor` 逐像素 0 误差**。

### 2.2 IP2-② CFAR：真实 std + 盒求和 O(1)

这是 PL 的核心难点，做了两层优化：

1. **不开方也不除法**：把浮点 `mean + k·sd + floor`（k=4.0）写成整数等价判决 —— 记 A=裁剪面积、S1=Σx、S2=Σx²，则 `x > mean+k·sd+floor` ⟺ `(x·A−S1−floor·A)² > k²·(A·S2−S1²)`。只需 4 个真乘法器（8x8、11x26、8x11、18x18；k²=16 和 WMAX 都是 2 的幂，综合成移位）**与 PS 侧参数严格一致**（早期用 `mean+5×MAD+3` 近似，差 1.4826 常数，已废弃）；
2. **盒求和 O(1)**：
   - **全帧版**（`cfar_threshold.v`）用 **2D 积分图** `integral[0:H-1][0:W-1]`：31×31 求和 = 4 次查表 + 3 次加减（O(961)→O(1)）；
   - **流式版**（`cfar_threshold_stream.v`，当前主线）**删掉积分图**（它必须整帧存储，做不到流式），改用 **`col_sum[]` 列和数组 + 31 项 FIFO + 环形延迟线**：每像素一次"加新减旧"即可同时得到 31×31 的行和/盒和，同样 O(1)，且全帧存储从 3.7 Mbit 降到 0。

边界采用**裁剪窗口**（窗口在图像边缘自然缩小、按实际像素数求均值）——比"复制边缘"更省硬件，是 FPGA 常见做法。

### 2.3 IP2-③ 候选提取：8 连通 CCL

二值图 → 8 连通域 BFS 洪泛 → 每个连通域算**质心/面积/峰值** → 按峰值降序取 top 5。
> topk 寻优（S 实测，双素材）：top5 与 top8 的**跟踪成功率完全相同**（97.0% / 89.7%），**ID 切换从 21 改善到 17**，虚警 −40%；候选缓冲存储减少 37.5%。

质心与软件严格对齐：`centroid = (sum_x + area/2) / area`。

### 2.4 IP3 后处理：NMS

- NMS 合并过近候选（矩形邻域 `|dx|≤3 && |dy|≤3`，免乘法）；
- **坐标保持降采样坐标（不 ×2）**——I2 约定 ×2 由 PS 显示时做；
- **坐标 16 位**输出，支持 640×360（坐标 0~639，超出 8 位上限 255）。

### 2.5b 流式版 IP2（当前主线，2026-10 重构）

为什么改：全帧版在 640×360 下要用 11 Mbit 存储（`img_bram` 1.84 + `mean_bram` 1.84 + `enh_bram` 1.84 + `label_bram` 1.61 + 延迟线 0.32 + …），Procise 首次综合出 **LUT 140,024 + LUTRAM 159,490（折合）≈ 器件的 381 %**，**物理上放不进器件**。改为流式后同一设计 **74 %**。

| 模块 | 关键结构 | 存储（640×360） |
|---|---|---|
| `win5.v` | 5×5 滑窗；4 条行缓存改成**循环 RAM**（深度 W+1，写指针 `wp`、读指针 `rp=(wp+1)%DEPTH`），延迟 2W+3；行抽头保留 5 深寄存器 | 2 实例 × 4 × 641 × 8 bit ≈ 40 Kbit（原为 41 K FF！） |
| `tophat_5x5_stream.v` | `erode(IS_MAX=0,PAD=255)` → `dilate(IS_MAX=1,PAD=0)`；原图经 `gd` 环形线延迟 `TD=4W+7` 后做差 | 2.5 K × 8 ≈ 20 Kbit |
| `cfar_threshold_stream.v` | **单趟融合**两个 31×31 因果盒同拍推进；虚拟光栅 `W30=W+30`、`H30=H+30`；`diff(t)=\|x(t−CENTER_OFF)−mean(t)\|`，盒2 中心落后 CENTER_OFF，故**两个盒各有自己的裁剪除数**；`dbuf1`(1写3读)/`dbuf2`/`mbuf` 三条环形线 | ≈ 516 Kbit |
| `candidate_extract_stream.v` | **单趟标记**：`lbl_even`/`lbl_odd` 两行交替 + 并查集（路径减半）+ 打标签时即时累加 `carea/csumx/csumy/cpeak`；`S_MERGE` 并入根、`S_POST` **每拍处理 1 个标签**（只有 2 个除法器，原先是 128 个并行除法器 = 9 万 LUT） | 0（只留 2×W×7 bit 行标签） |

> **反压**：CFAR 在虚拟光栅的 PAD 列会拉低 `i_ready`，因此顶层的 1 拍 1 位置必须一路反压回 Top-Hat（`i_ready` 端口贯通）。所有输出寄存器都只在 `o_ready` 有效时更新——这是"停顿后数据不错位"的必要条件（曾实测错 22~26 像素）。

### 2.6 IP4 ROI 打包：裁 128×128

- 按候选中心 `(cx,cy)` 裁 **128×128** ROI（左上角 `(cx−64, cy−64)`），**越界补 0**；
- 对齐 `ps_app.py::crop_roi`，对应接口 **I3**（`roi_data[128][128]` + `offset_x/y`）；
- 语义简单、无乘法，逐字节验证通过。

## 6 关键设计决策与创新点

| # | 决策/创新 | 说明 |
|---|---|---|
| 1 | **关闭 3×3 高斯** | 高斯专门打击半径 ≤1.5px 的小目标（Pd −45.7 点），而小目标正是本课题目标 |
| 2 | **CFAR 真实 std + 盒求和 O(1)**（平方比较判决） | 避开开方、可综合；**全帧版用 2D 积分图，流式版用列和+环形线（省掉整帧存储）**，两者都 O(1)，640×360 可实时 |
| 3 | **16 位坐标** | 支持 640×360，避免 8 位坐标溢出 |
| 4 | **非 2 幂宽度支持** | 行列索引用真除法/取余，而非位切片——修复了 320/640 宽度的隐藏 bug |
| 5 | **14 位精确灰度化** | 比 8 位系数多 1 LSB 精度，做到 0 误差 |

## 7 已知差异（如实注明）

1. **边界处理**：CFAR 的边缘用"裁剪窗口"（窗口变小、按实际像素数求均值），与 OpenCV 的 `REFLECT_101` 仅最外一圈不同（全帧版用 2D 积分图、流式版用列和+环形线，**两版逐位一致**）；Top-Hat 的 5×5 窗口在左右边界有 ≈6 % 像素的语义差异（已量化：旧全帧版同样差 185 处，属 OpenCV 边界语义而非重构引入）；目标均置于内部，不影响检测；
2. **真实 std 的代价**：多一条平方滑动盒（cs2/f2 加宽到 21 bit、rb3 加宽到 16 bit）+ 4 个真乘法器（两项 2 的幂常数乘综合成移位）；换来与 PS 侧 `k=4.0` 严格一致（早期 MAD 近似已废弃）；
3. **并列排序**：peak 相同时候选排列顺序未定义（不影响检测正确性，比对时按"峰值→x→y"规范排序）。

## 8 性能（640×360，流式版实测口径）

每帧约 **0.49 M 时钟周期**（= CFAR 虚拟光栅 670×390 = 261,300 拍 + CCL 单趟约 230,400 拍；Top-Hat/win5 与 CFAR 并行填充，不再单独计）：

| PL 时钟 | 每帧耗时 | 理论帧率 |
|---|---|---|
| 100 MHz | **2.5 ms** | 约 400 fps |
| 200 MHz | **2.5 ms** | 约 400 fps |

> 旧文档曾写"约 14N ≈ 3.2 M 周期 / 100 MHz 32 ms"，那是**未流水线化时的保守估算**（含整帧存取的等效代价），流式化后已被上式取代。综合资源：LUT 44,610 + LUTRAM 折合 13,536 = **58,146 / 78,600 = 74 %**，FF 19,474，块 RAM 0。

相机为 720P30（33.3 ms/帧），PL 处理 2.5~5.0 ms **约占 8~15 %，不是瓶颈**；瓶颈是 PS 侧的检测 57.87 ms 与渲染 88.89 ms。

## 10 后续优化方向（备忘，供后续加分）

**时域增强模块**（S 提议，软件实测候选 −75%、虚警 −95%、跟踪成功率持平）：
- 原理：帧缓存 N 帧 → 按速度参数**整数移位对齐**（PL 免费，移位是硬件强项，免插值/浮点）→ 累加求平均；
- **帧缓存放哪（预算已清楚，2026-10-23）**——一帧 640×360×8bit = 1.84 Mbit，N=16 需 29.5 Mbit > 板卡 PL 的 **9.3 Mbit BRAM**，放不下。**现状有利**：流水线化后 IP2 **块 RAM 用量为 0**（存储全用 LUTRAM），9.3 Mbit BRAM 完整空余 → **N=4（7.4 Mbit）可直接用块 RAM 实现**；N=8/16 需走 DDR（PS 侧搬数，PL 优势打折）或对帧缓存降采样。
