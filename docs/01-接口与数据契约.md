# 低小慢检测跟踪系统 · 接口与数据契约

> 平台：复旦微 FMQL30TAI-悟净 lite ｜ 2026 全国大学生嵌入式芯片与系统设计竞赛 · FPGA 创新设计赛道
> 本文定义系统内部 5 个数据接口的字段、单位与坐标系，以及各模块的替换方式与验收标准。

---

## 0. 文档范围

系统按 PL / NPU / PS 三段划分，三段之间的数据传递必须遵守本文定义的契约。内容包括：

1. 每个接口的字段级定义（谁产出、谁消费、什么格式、什么坐标系）；
2. 各模块的替换方式与验收标准；
3. 集成过程中实际遇到过的坑与预防方法。

---

## 1. 系统总览

### 1.1 流水线（7 个环节，对应 5 个接口）

```
 ①采集 ②检测(粗筛) ③裁ROI ④判别(精判) ⑤跟踪
 ┌──────────┐ I1 ┌──────────┐ I2 ┌────────┐ I3 ┌────────┐ I4 ┌────────┐
 │ 视频输入 │───────►│ PL:预处理 │─────►│ 裁图块 │───►│ NPU │───►│ CPU │
 │ PS:V4L2 │ │ +CFAR │ │ 128×128 │ │ ROI判别 │ │ 卡尔曼 │
 └──────────┘ └──────────┘ └────────┘ └────────┘ │ +航迹 │
 └───┬────┘
 ⑥显示 ◄─────────┘
 ⑦上报(JSON)
```

### 1.2 七个处理环节 ↔ 五个数据接口

**最常见的混淆点**："7"是处理环节（函数），"5"是数据接口（跨模块传递的数据契约）。

| # | 处理环节（函数） | 是否可替换 | 涉及的数据接口 |
|---|---|---|---|
| ① | `capture` 采集 | 可替换 | 产出 **I1** |
| ② | `detect` 检测（粗筛） | 可替换 | 消费 I1 → 产出 **I2** |
| ③ | `crop_roi` 裁 ROI | 可替换 | 消费 I2 → 产出 **I3** |
| ④ | `RoIJudge` 判别（精判） | 可替换 | 消费 I3 → 产出 **I4** |
| ⑤ | `Tracker` 跟踪与航迹管理 | 固定（CPU 内部） | 消费 I4 → **不产生跨模块接口** |
| ⑥ | `render` 显示叠加 | 可替换 | 产出 **I5-a**（HDMI 画面） |
| ⑦ | `report` 告警上报 | 固定（CPU 内部） | 产出 **I5-b**（串口/UDP 的 JSON） |

为什么不是 7 个接口：

- ⑤ 跟踪全程在 CPU 内完成，输入来自 I4、输出直接交给显示环节，**不跨越任何模块边界**，所以不需要独立接口；
- ⑥ 显示和 ⑦ 上报都属于"系统输出"，性质相同，合并为一个输出接口 I5（含画面、JSON 两个通道）。

**判断标准**：只有跨模块（PS↔PL↔NPU）传递的数据才需要定义接口；模块内部的中间数据用不着。

**替换点统计**：7 个环节中，**5 个可替换**（① 采集、② 检测、③ 裁 ROI、④ 判别、⑥ 显示），对应 `ps/ps_app.py` 里标注的"替换点 1~5"；⑤⑦ 固定不动。

### 1.3 接口变更的处理

接口字段、单位或坐标系发生变化时，按以下顺序处理：

1. 更新本文第 2 节的定义；
2. 同步修改生产方与消费方的代码，不能只改一侧；
3. 在本文件末尾的变更记录中登记日期、内容与依据。

## 2. 接口定义（字段级）

> **通用约定**：所有坐标、尺寸都以降采样图（640×360）为基准，除特别注明外。
> 例外：I1 的尺寸是原图（1280×720）、像素格式是彩色 BGR，见 I1 说明。
> 除 I1 外，像素格式统一为 灰度 uint8（0—255），内存**行优先连续**存放。

### I1 · 帧输入（PS → PL）

> **分工说明**：灰度化 + 2× 降采样由 PL 的 IP1 完成（数据量大、规则固定的像素级运算适合 FPGA）。
> 因此 PS 侧只负责采集与调度，直接把**原始彩色帧**交给 PL；PL 内部产出灰度图后再交给 IP2。

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `frame_id` | uint32 | 递增 | 帧序号，用于同步与丢帧检测 |
| `ts_us` | uint64 | 微秒 | 采集时间戳，用于算端到端延迟 |
| `width`,`height` | uint16 | **1280, 720** | 分辨率（**原图尺寸**，未降采样）|
| `format` | uint8 | 0 | **0=BGR 三通道 8 位**（彩色格式；灰度化由 PL 的 IP1 完成）|
| `data` | uint8[] | 0—255 | 像素数据，行优先 |

**约定**：乒乓双缓冲（PL 写 A 块时 CPU 读 B 块），用 `frame_id` 校验。

**产出**：PS（采集线程）｜ **消费**：PL（IP1）

---

### I2 · 候选列表（PL → PS/NPU）最容易出错

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `n_cand` | uint8 | **0—5** | 本帧候选数量（实测最优上限，见下）|
| `x[i]`, `y[i]` | uint16 | 0—639 / 0—359 | **候选中心坐标（降采样图坐标）** |
| `area[i]` | uint16 | 1—200 | 连通域面积（像素） |
| `peak[i]` | uint8 | 0—255 | 峰值强度 |

**排序约定**：按 `peak` **降序**，只保留前 `n_cand` 个。

> 为何上限取 5（2026-10-04 实测更新）：`Pd@topK` 分析显示，目标进入 **top3** 之后，扩到 top8 的检出率仅提升 0.6~0.8 个百分点（#4~#8 基本为杂波虚警）。
> 跟踪链路对比（飞鸟 720P / 1080P 双素材）：`topk=8` 时跟踪成功率 97.0%/89.8%、ID 切换 19/21、虚警 7826/6833；`topk=5` 时为 97.0%/89.7%、19/17、4563/4171 —— 跟踪不降而虚警降约 40%。
> 取 5 而非 3 是因为 `topk=3` 在 1080P 素材上 ID 切换由 21 恶化到 29。

**产出**：PL（IP2）｜ **消费**：PS（裁 ROI）

> 坐标系是本项目第一号坑：`x,y` 必须是**降采样图坐标**（640×360）。
> 显示时要 **×2** 换回原图坐标；写回 PL 时不要再乘。

---

### I3 · ROI 图块（PL → NPU）

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `roi_data` | uint8[128][128] | 0—255 | 灰度图块，**越界补 0** |
| `offset_x`,`offset_y` | int16 | — | 该 ROI 左上角在**降采样图**中的坐标 |
| `size` | uint16 | 128 | 图块边长（当前固定 128） |

**将来上板时**：`roi_data` 要改为 **INT8**，并附上量化参数（`quant_scale`、`zero_point`），必须与训练时的参数完全一致。

**产出**：PL（IP4）｜ **消费**：NPU

> 参考实现：`ps/ps_app.py` 里的 `crop_roi(gray, cx, cy, size=128)` → 返回 `(roi, (x0, y0))`

---

### I4 · 判别结果（NPU → PS）

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `score[i]` | float32 或 int8 | 0—1 | 目标置信度 |
| `class[i]` | uint8 | 0/1 | 0=背景，1=目标（当前只区分两类） |

**判定阈值**：`score ≥ 0.60` 视为通过（阈值可配置，见 `ps_app.py` 的 `CONF_TH`）。

**产出**：NPU ｜ **消费**：PS（跟踪）

> 参考实现：`ps/ps_app.py` 里的 `RoIJudge.__call__(roi) -> float`
> **对判别模型的要求**：ONNX 模型输入 128×128（灰度单通道或 3 通道复制），输出各类 logit/概率；**必须同时提供归一化参数**（`(x/255 - mean)/std` 的 mean/std）。

---

### I5 · 显示与告警（PS → 屏幕/上位机）

**画面元素**：原始帧 | 结果叠加（灰=候选 / 青=通过判别 / 绿=航迹框+ID+轨迹线 / 黄=真值）| 流水线状态面板

告警 JSON（每帧一行，写入 `.jsonl`，将来走串口/UDP）：

```json
{"ts":1790754698.738,"frame":2,"fps":null,"lat_ms":null,
 "alert":{"level":"warn","track_id":1,"bbox":[146.9,166.0,28,28],"conf":1.0,
 "speed_px_frame":0.38,"dir_deg":8.8,"age_frames":3}}
```

| 字段 | 说明 |
|---|---|
| `level` | `notice`（age<3）/ `warn`（conf≥0.6 且 age≥3）/ `critical`（conf≥0.85 且 age≥10） |
| `bbox` | `[左上x, 左上y, 宽, 高]`，**降采样图坐标** |
| `speed_px_frame` | 速度（像素/帧），由卡尔曼状态导出 |
| `dir_deg` | 运动方向（度） |
| `age_frames` | 该航迹累计命中帧数 |

---

### 真值标注文件格式（评测用，`xxx_gt.csv`）

```
frame,x,y
0,320.0,360.0
1,321.2,360.4
...
```

| 规定 | 说明 |
|---|---|
| 文件命名 | 必须与视频**同名同目录**：`seq01.mp4` + `seq01_gt.csv`（脚本会自动查找） |
| `x, y` 坐标系 | **原图坐标（1280×720）**，不是降采样坐标 |
| 缺帧处理 | 目标不在画面中的帧**不写入**该文件（脚本按"有真值的帧"统计） |
| 生成方法 | `python tools/mark_gt.py --src <视频>`（点几下自动插值，实测误差 0.55 像素） |

## 4. 模块替换与验收

### 4.1 检测模块（PL）

替换点 2、3：按 I1/I2 定义实现 `preproc_axis.v`（**灰度化 + 2× 降采样**，无高斯；高斯已由消融实验决定关闭，见 `docs/05-技术路线.md` D1）。

| 步骤 | 做什么 | 参考 |
|---|---|---|
| 1 | 写增强检测链路（4 个模块）：`tophat_5x5.v` + `cfar_threshold.v` + `candidate_extract.v` + `ip2_top.v` | 算法基准 `baseline/detect_v1.py` |
| 2 | 写 `roi_pack`（裁 128×128） | `ps/ps_app.py::crop_roi` |
| 3 | 写 Testbench，用 Python 的输出当期望值逐像素比对 | 容差：灰度/滤波 ≤2 LSB |
| 4 | 综合后检查资源报告；实现后检查时序（WNS ≥ 0） | — |

**验收**：同一段视频跑两遍，比对候选坐标，坐标差 ≤2 像素、数量一致。

### 4.2 判别模块（NPU）

替换点 4：把裁剪图块送 NPU 推理，替代软件判别。

| 步骤 | 做什么 |
|---|---|
| 1 | 准备数据集（自采 + 公开集），标注 ROI 正/负样本；负样本优先取自粗筛的真实虚警 |
| 2 | 训练 ROI 判别网络（输入 128×128，输出 2 类） |
| 3 | 导出 ONNX（固定输入尺寸，无动态维度） |
| 4 | 转换 + INT8 量化 + 精度分析，记录 FP32 与 INT8 的差异 |
| 5 | 交付：ONNX（PC 用）+ 板端模型 + 归一化参数 |

**验收**：同一批 ROI，PC(ONNX) 与 NPU(INT8) 的置信度差 ≤0.05。

### 4.3 跟踪与显示（PS）

| 职责 | 具体 |
|---|---|
| 集成骨架 | `ps/ps_app.py`（7 个环节、5 个替换点） |

## 5. 注意事项与常见坑

| # | 坑 | 症状 | 预防 |
|---|---|---|---|
| 1 | **坐标系混用** | 框画到错误位置 | I2 的坐标一律是**降采样图**坐标；显示时 ×2 |
| 2 | **归一化/量化参数不一致** | NPU 分数比随机还差 | I3/I4 的 mean/std、scale、zero_point 与训练时**完全一致** |
| 3 | **通道顺序不一致**（灰度/RGB/BGR） | 目标检不出 | **I1 是 BGR 三通道（彩色）**；I2 之后才是灰度；不要中途换格式 |
| 4 | **帧尺寸不匹配** | `Failed to write frame`、视频 0 字节 | 写入器尺寸必须等于实际画面尺寸（用 `assert` 断言） |
| 5 | **缓冲区不同步** | 画面与框错位一帧 | 用 `frame_id` 校验；乒乓缓冲 |
| 6 | **丢帧无人管** | 延迟越积越大 | 队列满时**丢最旧帧并计数**，绝不阻塞 |
| 7 | **用手持视频做时域** | 增强/跟踪全失效 | 拍摄**必须用三脚架** |
| 8 | **真值坐标系搞错** | Pd 算出来接近 0 或 100% | `xxx_gt.csv` 用**原图坐标**（脚本内部会 ÷down） |
| 9 | **大文件提交进仓库** | 仓库膨胀、push 卡死 | 视频/数据集/模型单独存放，`.gitignore` 已覆盖常见类型 |
