# 检测系统指标评估（2026-11-02）

> 对照学术界与工业界通用指标，评估当前"PL 粗筛 + NPU 精判"三域系统的真实水平。
> 所有"实测"数据来自本仓库 `ps/` 下的脚本，板上运行。

## 一、通用指标体系（三类）

### 1. 精度类
| 指标 | 定义 | 说明 |
|---|---|---|
| **Precision (P)** | TP/(TP+FP) | 报出来的框里有多少是真的 |
| **Recall (R)** | TP/(TP+FN) | 真的目标有多少被找到 |
| **F1** | 2PR/(P+R) | P/R 的调和平均 |
| **AP@IoU** | PR 曲线下面积，IoU 阈值 0.5（PASCAL）或 0.5:0.95（COCO） | 单类平均精度 |
| **mAP@0.5** | 各类 AP 的平均 | 最常引用的单一指标 |
| **AP_small** | 面积 <32² px 的目标 AP | **小目标检测的核心指标** |

参考：[COCO 指标体系](https://www.mdpi.com/2072-4292/13/13/2582/pdf-vor)、[小目标检测综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC13245754/)

### 2. 效率类
| 指标 | 定义 | 典型要求（边缘设备） |
|---|---|---|
| **FPS** | 每秒出图数 | 实时 ≥25~30 |
| **单帧延迟** | 一次推理耗时 | 越低越好 |
| **端到端延迟** | 采集→出结果 | 实时监控 <100 ms |
| **功耗 / TOPS** | 能效比 | 电池场景关键 |

### 3. 资源类
LUT / BRAM / DSP 占用率、时序余量（WNS）、内存带宽。

## 二、我们的实测值

### 2.1 效率类（板上实测）

| 指标 | 实测值 | 评价 |
|---|---|---|
| **画面帧率**（解耦后） | **18.1 fps**（离线写 mp4）；真实网页受相机限 30 fps | ⚠️ 离线受编码限，线上可达 |
| **检测频率** | **10.8~11.5 Hz**（83 ms/次） | ⚠️ 低于 15 Hz，快速目标框会滞后 |
| **单帧串行耗时** | 77.7 ms | ❌ 12.9 fps，不满足实时 |
| **PL 检测** | **23.1 ms** | ⚠️ 早期是 4.19 ms，退化了 5 倍（未定位） |
| **NPU mosaic**（16 个候选） | **32.5 ms**（4.24 ms 前向 + 读取解码） | ⚠️ 读张量占大头 |
| **端到端延迟** | 46~85 ms（检测单次） | ✅ 满足 <100 ms |

| 指标 | 实测值 | 样本 | 评价 |

| **Precision** | **76.6%** | 同上 | ✅ 尚可 |
| **F1** | **≈57%** | 计算值 | ❌ 低 |

## 三、与典型基线对比

| 系统 | 平台 | mAP@0.5 | FPS | 备注 |
|---|---|---|---|---|
| YOLOv8n（裁剪版） | GPU | 37~45（COCO） | 100+ | 通用目标 |
| 轻量小目标检测（文献） | Jetson/边缘 GPU | 60~75 | 30~60 | 专用数据集 |
| **本项目** | **FPGA+NPU 异构** | **未测（估 40~55）** | **11（检测）/18（画面）** | 自研 PL 预处理 |

**结论：精度大概在"能用"区间，效率不达标，指标不完整。**

参考：[DAN-YOLO-L 红外小目标](https://link.springer.com/article/10.1038/s41598-026-56734-9)、[GS-YOLO 无人机航拍小目标](https://pmc.ncbi.nlm.nih.gov/articles/PMC13245754/)

## 四、差距与补齐建议（按重要性）

### P0｜补 mAP（1~2 小时，必须做）
现在所有精度结论都是"看图说话"，答辩会被问穿。

做法：
1. 用六张图人工标注真值框 JSON
2. 跑检测 → 按 IoU≥0.5 匹配 → 算 TP/FP/FN
3. 输出 Precision / Recall / F1 / AP@0.5
4. 按目标面积分层统计 **AP_small（<32²）/ AP_medium / AP_large**

### P1｜把 FPS 拉回 25+（已量化，可达）
```
INTER_LINEAR            -4.5 ms
NPU 隔帧                -16 ms
推流 512×288            -8.8 ms
────────────────────────────────
77.7 → 48.4 ms → 20.7 fps
```
若抛掉"彩色推流"约束可到 25 fps。

### P2｜查 PL 23.1 ms 退化（4.19 → 23.1）
这是 5 倍退化，原因未定位。可能是触发轮询、AXI 读延迟或 CCL 规模。

### P3｜修时序（WNS −0.031）
现在靠运气收敛，任何改动都可能失败。

### P4｜扩窗口（SE=5 → 更大）
t4 四架 150 px 目标检不到，是窗口硬限制。但 SE=9 布线拥塞 172%，需要先腾资源。

## 五、一句话总结

> **精度：粗估召回 54% / 精确 55%，无 mAP，小目标能力未量化。**
> **效率：检测 11 Hz，端到端 46~85 ms，串行 12.9 fps 不达标。**
> **资源：LUT 84%、时序未收敛，扩容空间几乎没有。**

三条硬伤按优先级：**补指标 > 提帧率 > 查退化**。
