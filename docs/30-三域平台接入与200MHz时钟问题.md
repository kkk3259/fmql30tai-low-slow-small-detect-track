## 2. 卡住的地方

配进去以后：**PS 侧任何寄存器访问都会挂死 AXI 总线**（读 `0x400C0000` 无响应），整板冻结需断电；runtime 的 DMA 也报 `DMA Read time out (5000 ms)`。

### 根因（Vivado 时序报告实证）

最差路径：

```
Slack (VIOLATED) : -11.938ns
Source:      U_ip2_op/u_ip2/u_chain/u_cfar/wpa_reg[2]_replica/C
Destination: U_ip2_op/u_ip2/u_chain/u_cfar/q1_ws2_reg[25]/D
Clock:       clk_pll_i  rise@0.000 fall@2.500  period=5.000ns   ← 200 MHz
Data Path Delay: 16.828ns  Logic Levels: 38 (CARRY4=12, LUT…)
```

- 平台的数据口时钟 `hp_clk` 实际是 **200 MHz**（5 ns），我们的 IP2 核心被接在这个时钟上；
- 我们核心的关键路径是 **16.8 ns（≈57 MHz 上限）**，在 200 MHz 下必然出错；
- 出错后 FSM 卡住、`arvalid` 长高，把 PL-DDR 读通道占死 → runtime DMA 超时 → 整板 AXI 挂死。

**对照**：独立版（`ip2_bd_wrapper`，50 MHz）WNS +2.5 ns、29 fps 正常 —— 同一个核，只是时钟快了 4 倍。

## 3. 修复方案（下次直接做）

在 `ip2_user_op.v` 里：

1. 用 `hp_clk` 四分频得到 50 MHz（`clk_div4`，与 hp_clk 同源，**不是异步 CDC**，跨时钟只用 2 拍打拍 + 握手 toggle 即可安全）；
2. 整个 `ip2_axi_top`（含 AXI 主口）跑 `clk_div4`；
3. 平台的 512 位读写口留在 `hp_clk`，与 `clk_div4` 之间加一级“行有效 + ack”握手桥（数据在握手期间保持稳定）；
4. 寄存器口 `ra_clk`（gp_clk 50 MHz）本来就独立，保持不变。

预计改动 `ip2_user_op.v` 约 80 行，重编译 25 分钟，资源不变。

## 4. 板上现状与恢复步骤

- 板子被挂死，需**断电重启**（P 无法远程做）。
- 重启后跑 `D:\firstharness\dl\_recover.sh`（scp 到板上执行）：
  - `echo ip2_bd_wrapper.bin > /sys/class/fpga_manager/fpga0/firmware`
  - `/etc/init.d/ip2demo restart`
  - 检查 `/info` 的 fps / PL / raw / stable
- 恢复后即回到“网页实时检测 + 29 fps”的可用状态。

## 5. 结论

- 三域平台的**编译与加载**已经通了，这是今晚最大的突破；
- 但“检测器跑在平台里”还差**时钟适配**这一步，原因明确、方案明确，不是未知问题；
- 在时钟修好之前，**不要**在平台上跑我们的检测器（会挂死整板）。
