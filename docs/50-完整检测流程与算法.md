# 低小慢目标检测：完整流程与算法（2026-11-02 版）

> 本文档把当前板子上跑的**全部检测流程与算法**按数据流顺序写清楚，用于比赛文档与答辩。
> 所有数字均为板上实测，测量脚本在 `ps/`。

---

## 一、总体架构：三域分工

```
摄像头(USB UVC) → PS 取帧 → PL 粗筛 → PS 裁 ROI → NPU 精判 → PS 跟踪/画框 → 网页推流
                    ↑                        ↑            ↑
                    ARM Cortex-A9           FPGA        AI_Mate NPU
```

| 域 | 器件 | 职责 | 每帧耗时 |
|---|---|---|---|
| **PS** | ARM A9 ×2 | 取帧、预处理、裁 ROI、拼图、跟踪、编码、HTTP | 见第五节 |
| **PL** | FPGA 逻辑 | Top-Hat → CFAR → CCL，输出候选点 | **23 ms** |
| **NPU** | AI_Mate (ZG330) | YOLO11n 判定候选是否为无人机 | **32 ms**（隔帧 16） |

**设计原则**：PL 便宜地筛掉 99.99% 像素（640×360=230,400 → 约 8 个候选），NPU 只看这几个候选的小图。

## 二、PL 层算法（`pl/rtl/`）

### 2.1 输入
640×360 灰度（8 bit），由 PS 写入 DDR，PL 通过 AXI-HP 用 512 位突发读入。

### 2.2 Top-Hat 形态学（`win5.v` + `tophat_5x5_stream.v`）

```
Top-Hat = 原图 − 开运算(原图, SE)
开运算 = 膨胀(腐蚀(原图, SE), SE)
```

- 结构元 SE = 5×5（可参数化；SE=9 布线拥塞装不下）
- 实现：4 个行缓冲 + 5 个行抽头构成 5×5 滑动窗；行内极值用**两段平衡树**（`minmax_tree.v`）取代 441 抽头的比较链，逻辑层数 60→10
- 作用：**抹掉大面积缓变背景**，只留下比 SE 小的亮斑（暗目标靠 PS 侧取反变成亮斑）

### 2.3 CFAR 恒虚警检测（`cfar_threshold_stream.v`）

与常规 CFAR 不同，这里用**局部统计 + 平方判决**避免开方和除法：

```
局部窗 31×31 内统计：
  A  = 有效像素数        （裁剪边界后，最大 961）
  S1 = Σx
  S2 = Σx²
  μ  = S1 / A
  σ² = S2/A − μ²

判据（等价于 x > μ + k·σ + floor，但不开方）：
  L  = x·A − S1 − floor·A
  L² > k²·(A·S2 − S1²)

位宽：S1 18b, S2 26b, A·S2 37b, S1² 36b, L 20b, L² 38b
```

- k = 4（k²=16 变成左移 4 位）
- floor = 3
- 流式实现：滑动盒 O(1) 更新（31 行延迟线 `rb1[20306×8]` + 列和 `col_sum[0..W+14]` + 31 项 FIFO），两遍扫描（先求均值、再算 MAD）
- 中心窗口：`col_sum` 加宽到 W+15，列计数在 W+14 回绕，消除上下死区

### 2.4 连通域标记（`candidate_extract_stream.v`）

- 两遍扫描：第一遍按行建立**并查集**（路径减半），第二遍收集
- 8 连通、单趟流式
- MAX_COMP = 64，MAX_CAND = 32
- 输出每条候选：`x(16b) y(16b) area(16b) peak(8b)`，按 peak 降序
- **边界抑制** `BORDER=24`：上下左右各 24 px 内的候选 peak 清零（消除 pad 假目标）

### 2.5 输出与读回
- 候选表写到 AXI-Lite 窗口（`0x400C0010`，113 字节兼容视图在 `0x18~0x38`）
- PS 用 `mmap(/dev/mem)` 直接读

## 三、PS 层算法（`ps/`）

### 3.1 预处理
```python
gray = cv2.resize(cvtColor(frame, BGR2GRAY), (640,360), INTER_AREA)   # 8.4 ms
gray = 255 - gray        # 可选：暗目标（亮天空里的鸟）
```

### 3.2 候选后处理（顺序很重要）

| 步骤 | 算法 | 参数 |
|---|---|---|
| ① 有效过滤 | `area≥4, peak≥8, 边距≥8` | |
| ② **相位修正** | `x = (x + X_SHIFT) % W` | X_SHIFT=64（实测恒定）|
| ③ **空间分散** | 按 peak 降序贪心，彼此间距 ≥40 px | 防止树线虚警占满格子 |
| ④ **中心距聚类** | `r = clamp(2.5·√area, 14, 40)`，中心距 ≤ r 合成一个 | 同一目标的碎片合一 |
| ⑤ 取前 16 | `[:16]` | 4×4 mosaic 格子数 |

**③④ 是关键**：不做③，t3 的树线虚警会占满 16 个格子；不做④，一架无人机碎成 6 个候选。

### 3.3 ROI 裁剪 + mosaic 拼图
```python
side = clamp(3.0·√area, 96, 128)      # 按面积自适应，把小目标放大 3~5 倍
crop = gray[y0:y0+side, x0:x0+side]
mosaic = 4×4 网格，每格 160×160，灰底 114
```

### 3.4 NPU 判定（`yolo_det.py`）

**模型**：`yolo11n_drone_trunc_ZG.raw`（A 提供，无人机专用）
**输入**：`[1,640,640,3]` NHWC uint8，**letterbox**（不是拉伸！）
**输出**：`OUT0 [1,64,8400]` + `OUT1 [1,1,8400]`（int8 量化 logits，步长 0.8066）

**解码（YOLOv8 anchor-free）**：
```python
score = sigmoid(out1) · max(sigmoid(out0[4:]))       # objectness × 类别
# 先取 60 类最大 logit 再 sigmoid（数学等价，快 15 倍：45.7ms → 3ms）
l,t,r,b = a[0:4]·4                                    # 距离式
x1 = (gx+0.5-l)·stride ;  y1 = (gy+0.5-t)·stride
x2 = (gx+0.5+r)·stride ;  y2 = (gy+0.5+b)·stride
x1,y1,x2,y2 → 减 letterbox 偏移、除缩放比 → 回原图坐标
```
- 8400 = 80²+40²+20²（stride 8/16/20）
- 阈值 CONF=0.45，IOU/NMS=0.30
- **forward 4.24 ms**（一次判 16 个候选）

### 3.5 框合并与平滑

| 步骤 | 算法 | 参数 |
|---|---|---|
| ⑥ **50% 包含度合并** | `交集/min(面积) ≥ 0.50` → 合成外接框 | 一个目标一个框 |
| ⑦ **EMA 平滑** | `pos = 0.65·旧 + 0.35·新` | A=0.35 |
| ⑧ **航迹保持** | 丢帧时用上次位置顶 `MISS=4` 帧 | 消除闪烁 |
| ⑨ **保护区重检** | 已确认(≥6帧)的航迹丢失时，预测位置裁 128×128，**CONF 降到 0.20** 再判一次 | hit/f 1.20→1.57 |

### 3.6 显示
- 绿色框 = NPU 确认（p≥0.45），标签为百分比
- 橙色框 = 确认但分数低
- 淡灰细框 = PL 候选但 NPU 未确认（1 px，不写字）
- 前端 canvas 矢量绘制（不烧进 JPEG，保证清晰）

### 3.7 推流
- **解耦架构**：画面线程（取帧→编码→推流）与检测线程完全独立
- MJPEG over HTTP：`/stream`（实时流）、`/snap?q=90`（截图）、`/info`（JSON 状态）
- 彩色输出（观感），JPEG q70

## 四、算法取舍记录

| 尝试 | 结果 | 结论 |
|---|---|---|
| 80% 包含度合并 | 仍有重叠框漏合 | 降到 **50%** 才干净 |
| 自适应半径合并（不聚类） | t4 四架并成 3 框 | 改用**中心距聚类** |
| 按 IoU 去重 | 碎片框不重叠，无效 | 碎片中心距小 → **距离判据有效** |
| NEAREST 缩放 | 快 7.5 倍但漏小目标 | 不用 |
| 灰度推流 | 省 13.6 ms | 观感不可接受，**保留彩色** |
| JPEG 降质量 q85→q50 | 只省 0.4 ms | 无效，不降 |

## 六、已知限制

1. **SE=5 太小**：中大型目标只剩边缘碎片；SE=9 布线拥塞 172% 装不下
2. **CFAR 受高对比背景影响**：鸟飞过白云时局部 σ 被抬高 → 零候选
3. **列相位 +64 恒定偏移**：适配层无帧级清 FIFO；PS 侧硬编码修正
4. **t4 四架大目标**：150 px 超出 28 px 窗口，检不到
5. **单帧耗时两种口径**：PS 侧从触发到读完候选表为 23.1 ms，PL 内部处理为 4.19 ms；两者差值来自写帧、触发、等待与读表开销
