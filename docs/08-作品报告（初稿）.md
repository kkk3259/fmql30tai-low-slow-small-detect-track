# 低小慢空间目标智能检测与跟踪系统

## 摘要

低小慢目标（低空、小尺寸、慢速飞行目标，如小型无人机）的探测与跟踪是低空安防的核心难题：目标在图像中通常仅占几个到几十个像素，信噪比低、缺乏纹理与形状特征；同时云层、地物等背景杂波又会产生大量虚警。传统"先成像、再传回地面处理"的方式存在延迟大、带宽高、依赖链路等问题。

本作品基于复旦微 FMQL30TAI 异构平台（ARM 四核 + ZG330 NPU + 可编程逻辑），构建了一套端侧实时的低小慢目标智能检测与跟踪系统。系统采用 PS + NPU + PL 三级异构分工：PS 负责视频接入与流程调度；PL 承担图像灰度化与降采样、形态学增强、恒虚警率（CFAR）自适应检测、候选目标提取等像素级高强度计算；NPU 对 PL 输出的候选区域进行精判别；最后由跟踪环节完成多目标航迹管理。

我们采用"先软后硬、以软验硬"的工程方法：先在 PC 上用 Python/OpenCV 实现完整算法基线（v0 预处理、v1 检测、v2 跟踪），建立可复现的评测体系与真值标注流程；再把计算热点逐模块迁移到 PL，用 Verilog 实现后经逐像素自动比对验证，保证软硬件行为一致。

主要成果：软件基线在合成序列上检出率 94.7%、跟踪成功率 98.7%、航迹确认后虚警 0 次/分钟；通过参数化扫描实验量化了算法能力边界——目标对比度不高于 5 灰阶时单帧检出率趋近于 0，而对比度达到 15 灰阶以上时可达 94% 以上，这为 PL 端时域积累（多帧增强）模块的设计提供了直接依据；PL 端已完成预处理模块与检测链路（Top-Hat 形态学 + CFAR + 候选提取）的设计与仿真验证，内部像素误差不超过 1 个灰阶。

系统面向低空安防、机场周界、重要目标防护等应用场景，具备端侧实时、低带宽依赖、模块化可扩展等特点，也为后续扩展红外通道与多目标关联跟踪预留了接口。

（约 520 字）

# 第一部分  作品概述

## 1.1 功能与特性

本作品实现了一套面向低小慢目标的实时检测与跟踪系统，主要功能如下：

**（1）多源视频接入与预处理。** 支持 USB 摄像头（V4L2）与本地视频/图像序列回放两种输入方式，完成彩色到灰度的转换、2 倍降采样与去噪，将 1280×720 的输入压缩为 640×360 的灰度图，为后续处理降低数据量。

**（2）弱目标增强与自适应检测。** 采用 Top-Hat 形态学滤波抑制大面积背景（云层、地物），突出小尺寸亮目标；采用恒虚警率（CFAR）自适应阈值替代固定阈值，使检测门限随局部背景起伏自动调整，在云层边缘等复杂背景下仍能保持稳定的虚警水平。

**（3）候选目标提取与精判别。** 对二值化结果做连通域分析，提取候选目标的质心、面积、峰值等特征；对候选区域裁剪出 ROI，交由 NPU 上的轻量分类网络判"真目标/虚警"，实现"粗筛 + 精判"两级架构。

**（4）多目标跟踪与航迹管理。** 采用卡尔曼滤波预测 + 贪心匹配关联，支持多目标同时跟踪；通过"连续 N 帧命中才确认航迹、连续 M 帧丢失才删除"的机制抑制虚警，并为每个目标分配稳定 ID、绘制运动轨迹。

**（5）结果输出与可视化。** 实时叠加绘制检测框、目标 ID、轨迹线与统计信息，输出视频、CSV 数据表与 JSON 结构化结果，便于复盘与二次分析。

**（6）异构任务划分。** 依据计算特征把任务分配到 PS/NPU/PL：像素级重复计算交给 PL，特征级判别交给 NPU，流程控制与人机交互留在 PS，兼顾实时性与灵活性。

（约 440 字）

## 1.2 应用领域

**（1）低空安防与反无人机。** 面向机场、监狱、核电站、大型活动场馆等重点区域的低空入侵预警，对小型多旋翼、固定翼无人机实施早期发现与持续跟踪，为反制设备提供目标指示。

**（2）机场净空与飞行安全。** 机场跑道周边是无人机扰航的高发区，本系统可部署于塔台或场区高点，对进入净空区的低小慢目标进行实时告警与轨迹记录，辅助管制决策。

**（3）重要目标与要地防护。** 用于军事设施、能源基地、油库等要地的周界低空监视，可在不依赖高带宽回传链路的前提下就地完成检测，降低被干扰与链路中断的风险。

**（4）边境与海防监视。** 边境线上目标距离远、成像尺寸小，配合长焦镜头可对人员、小型船只、低空飞行器实施远距离监视与跟踪。

**（5）生态与农业监测。** 鸟群、飞行昆虫等低小慢目标的数量统计与轨迹分析，可用于机场鸟击预警、生态调查与精准农业。

**（6）通用嵌入式视觉平台。** 系统采用模块化设计，PL 端各 IP 与 PS 端各处理环节接口清晰，稍作裁剪即可迁移到其他小目标检测场景（如水面小目标、天文斑点、工业缺陷），具有较好的技术复用价值。

（约 400 字）

## 1.3 主要技术特点

**（1）PS + NPU + PL 三级异构分工。** 不追求"全部上 FPGA"或"全部用 NPU"，而是按任务的计算特征与数据依赖关系划分：PL 承担数据量大、逻辑规则明确的像素级运算；NPU 承担特征级的分类判别；PS 承担控制调度与结果输出。这种划分使得每一级都在自己最擅长的任务上工作。

**（2）软硬件一致的"以软验硬"流程。** 先在 PC 上用 Python/OpenCV 建立完整算法基线并验证指标，再用 Verilog 逐模块在 PL 上实现；每个 PL 模块都配套编写 Testbench 与激励生成脚本，用 OpenCV 生成"标准答案"，在仿真阶段做逐像素自动比对，量化误差。这样保证硬件实现与算法设计严格对齐。

**（3）CFAR 自适应门限替代固定阈值。** 固定阈值在云层边缘等背景剧烈起伏时会同时产生漏检与虚警；CFAR 通过局部均值与标准差动态计算门限，使系统在复杂背景下保持稳定虚警水平，这是本系统能在真实杂波环境下工作的关键。

**（4）时域积累与航迹确认双重抗虚警。** 从参数化实验中我们发现，单帧检测对低对比度目标几乎无效（对比度不高于 5 灰阶时检出率趋近 0）；因此设计上采用多帧时域积累提升信噪比，并配合"连续 3 帧命中才确认航迹"的逻辑，实测可将虚警从启用前的 5412 次/分钟降至 0 次/分钟。

**（5）平台约束下的工程可行性设计。** 针对所用开发板（轻量版）部分高速接口未引出、无实时时钟等硬件限制，数据通路统一规划为 PS 侧接入，避免依赖 SDI 等不可用接口，保证方案可实际落地。

（约 430 字）

## 1.5 主要创新点

**（1）参数化能力边界量化方法。** 提出用合成序列系统扫描"目标尺寸 × 对比度"参数网格，绘制检出率曲线来量化算法能力边界，为硬件模块（时域积累、CFAR 门限）的设计提供定量依据，而非依赖经验估算。

**（2）软硬件逐像素等价性验证。** 每个 PL 模块都建立"Python 参考实现 + 逐像素自动比对"的验证闭环，把软硬件差异量化为具体数值（如内部像素 ≤1 灰阶、边界像素 ≤3 灰阶），并明确定义可接受的误差口径。

**（3）面向资源约束的分级检测架构。** PL 做"粗筛"、NPU 做"精判"、PS 做"管理"，使昂贵的算力只用在少量候选区域上，显著降低 NPU 负载，提高整体吞吐。

**（4）可复现的工程化数据链。** 从数据生成、真值标注、指标评测到结果归档全部脚本化，固定随机种子，保证任何一次实验结果都可被队友独立重现与复核。

（约 300 字）

## 1.6 设计流程

本作品遵循"需求分析 → 软件基线 → 参数标定 → 硬件迁移 → 系统集成 → 联调评测"的流程：

1. **需求与约束分析**：明确目标特性（低小慢）、平台约束（可用接口、算力）与指标目标；
2. **软件基线开发**：在 PC 上用 Python/OpenCV 实现 v0 预处理、v1 检测、v2 跟踪三个版本；
3. **参数标定实验**：用合成序列扫描目标尺寸与对比度，量化能力边界，确定检测参数工作点；
4. **PL 模块实现**：按接口规范逐模块用 Verilog 实现，配套 Testbench 与激励生成脚本，仿真阶段与 OpenCV 参考逐像素比对；
5. **系统集成**：PS 端完成 7 个处理环节与 5 个数据接口的编排，预留 PL/NPU 替换点；
6. **联调与评测**：软硬件结果交叉验证，输出性能指标与对比分析。

（约 290 字）

# 第二部分  系统组成及功能说明

## 2.1 整体介绍

系统整体分为信号采集、预处理、目标增强、自适应检测、候选提取、精判别、跟踪输出七个处理环节，并按异构平台特点划分为 PS（ARM 应用处理器）、NPU（神经网络加速器）、PL（可编程逻辑）三个执行域。

整体数据流如下：

```
USB 摄像头 / 视频序列
        │  （PS 侧 V4L2 接入 / 文件回放）
        ▼
┌──────────────────────────────────────────────────────┐
│  PS（ARM 四核）                                       │
│   ① 采集与调度  →  ⑥ 结果输出与可视化                 │
│                      （叠加框、ID、轨迹、统计）        │
└───────────┬──────────────────────────┬───────────────┘
            │ 灰度帧（640×360）         ▲ 候选坐标
            ▼                          │
┌───────────────────────────┐   ┌──────┴──────────────┐
│  PL（可编程逻辑）          │   │  NPU（ZG330）        │
│   ② 预处理（灰度+降采样）  │   │   ⑤ ROI 精判别       │
│   ③ 形态学增强（Top-Hat）  │   │   （候选 → 真/假）   │
│   ④ CFAR 检测 + 候选提取  │──►│                      │
└───────────────────────────┘   └─────────────────────┘
            │
            ▼
   ⑦ 多目标跟踪与航迹管理（卡尔曼预测 + 数据关联）
```

各模块间关系说明：**PL 是整个系统的算力主体**，把数据量最大的像素级运算（灰度化、降采样、形态学、阈值检测）从 PS 卸载下来；**NPU 只处理 PL 输出的少量候选 ROI**，避免了对整幅图像做神经网络推理的巨大开销；**PS 不参与像素运算**，只做流程编排、数据搬运与结果呈现，同时保留纯软件实现作为兜底与对照。

（约 460 字）

## 2.3 软件系统介绍

### 2.3.1 软件整体介绍

软件系统由**三层**构成，自下而上为：

**（1）PL 硬件加速层**：用 Verilog 实现的图像处理 IP，运行于 PL 上，承担像素级流水运算。当前已完成预处理模块（灰度化 + 降采样 + 高斯去噪）与检测链路模块（Top-Hat 形态学 + CFAR 阈值 + 候选提取）。

**（2）PS 应用层**：Python（后续迁移 C++）实现的主程序，负责视频接入、流程编排、结果输出与人机界面，共 7 个处理环节、5 个数据接口，并为 PL/NPU 预留明确的替换点。

**（3）NPU 推理层**：轻量级卷积分类网络，对候选 ROI 做"真目标/虚警"二分类，模型经量化后部署到 ZG330 NPU。

此外，为保证开发质量与可复现性，还建立了**配套工具链**：数据生成与标注工具、指标评测工具、参数扫描实验工具、RTL 仿真复核工具。

**开发环境**：Ubuntu 20.04（板端）+ Windows（开发与仿真），Python 3.12 + NumPy + OpenCV，Icarus Verilog（RTL 仿真），GTKWave（波形查看），AIcraft（NPU 模型部署），Procise（FPGA 综合实现）。

### 2.3.2 软件各模块介绍

软件各处理环节（对应 1.2 节的数据流）及其输入输出如下：

| 环节 | 模块 | 关键输入 | 关键输出 |
|---|---|---|---|
| ① 采集与调度 | `capture_init` / 主循环 | 视频源（USB/文件） | 原始彩色帧 |
| ② 预处理 | 灰度化 + 降采样 + 高斯 | 彩色帧 1280×720 | 灰度图 640×360 |
| ③ 形态学增强 | Top-Hat 滤波 | 灰度图 | 增强图（背景被抑制） |
| ④ 自适应检测 | CFAR 双参数阈值 | 增强图 | 二值图 + 门限图 |
| ⑤ 候选提取 + 精判 | 连通域分析 + ROI 判别 | 二值图 + 增强图 | 候选列表 `[x, y, w, h, area, peak]` |
| ⑥ 跟踪 | 卡尔曼预测 + 贪心匹配 + 航迹管理 | 候选列表 | 航迹 `[id, x, y, vx, vy]` |
| ⑦ 输出与可视化 | 绘制 + CSV/JSON 输出 | 航迹 + 原始帧 | 标注视频、数据表 |

**5 个关键数据接口**（模块间的契约）：

| 接口 | 数据形态 | 说明 |
|---|---|---|
| I1 | 彩色帧（BGR 8 位 3 通道） | 采集 → 预处理 |
| I2 | 灰度/增强图（8 位单通道） | 预处理 → 增强 → 检测 |
| I3 | 二值图 + 门限 | 检测 → 候选提取 |
| I4 | 候选列表 | 候选提取 → 跟踪 / ROI 判别 |
| I5 | 航迹列表 | 跟踪 → 输出 |

**关键函数说明**（以检测与跟踪为例）：

- `adaptive_threshold(img, win, k, floor)`：以局部窗口（默认 31×31）计算均值与标准差，门限 = 均值 + k×标准差，并施加最低门限 floor，返回二值图与门限图。若裁剪为硬件加速，对应 PL 的 CFAR 模块。
- `extract_candidates(binary, enh, min_area, max_area, topk)`：对二值图做连通域标记，按面积过滤后输出候选，返回候选的质心、外接框、面积与峰值强度。
- `crop_roi(gray, cx, cy, size)`：以候选质心为中心裁剪 ROI（默认 128×128），供 NPU 判别。
- `Track.step(dets)`：对每条航迹做卡尔曼预测，与当前帧检出行做贪心匹配（匹配门限 gate），更新命中/丢失计数，完成航迹确认与删除。

**★ 硬件替换点**：PS 应用中有 5 处标注为"替换点"的位置——采集（换 V4L2/VPU 硬解）、预处理与检测（换 PL 的 AXI4-Stream 输出）、精判别（换 NPU 推理），保证软件架构在硬件就绪后可以平滑替换，而无需重构整体流程。

**能力边界实测**（重要结论）：

| 目标对比度 | 半径 1.0 px | 半径 1.5 px | 半径 3.0 px |
|---|---|---|---|
| 5 灰阶 | 0% | 0% | 0.8% |
| 15 灰阶 | 31.7% | 94.2% | 100% |
| 30 灰阶 | 85.0% | 100% | 100% |

该结果表明：**目标对比度是决定单帧检出能力的主导因素**——当对比度降至 5 灰阶时，即使目标尺寸较大也无法检出，这直接证明了多帧时域积累的必要性，也为 PL 模块的参数设计提供了依据。

# 第四部分  总结

## 4.1 可扩展之处

1. **时域积累模块**：在 PL 端增加多帧差分/背景滑动平均模块，把低对比度目标的检出率从当前不足 1% 显著提升，这是已由实验数据证明的最有价值方向。
2. **红外通道扩展**：增加红外图像输入通路，实现可见光/红外双波段互补（夜间与弱光场景），可采用公开红外数据集先做离线验证。
3. **PL 架构流水线化**：把当前"存全图再处理"的结构改为"行缓存 + 流水线"，以支持 1280×720 等高分辨率的实时处理。
4. **候选提取精确化**：当前 PL 端采用分块粗筛，后续可实现连通域标记（CCL）以获得精确质心与面积。
5. **NPU 模型完善**：扩展分类网络的训练数据与类别，并探索轻量化检测网络直接在候选区域做端到端判别。
6. **多目标关联增强**：引入更稳健的数据关联算法（如匈牙利算法）与外观特征，提升目标交叉、遮挡场景下的跟踪连续性。
7. **标准化接口**：把 PL 模块接口统一为 AXI4-Stream，便于与官方参考设计或其他图像处理 IP 级联。
8. **预测性扩展**：基于航迹速度估计实现目标运动趋势预测与越界报警，对接反制设备形成闭环。
