**本文用途**：P 给出 `.hdf` 之后，S 照本文把位流装进 `BOOT.bin`、上板、跑通 PS↔PL 的第一次握手。

## 0. 一句话流程

```
P 出 .hdf  →  S 用 SDK 重打 BOOT.bin（FSBL → bit → bl31 → u-boot）
```

## 2. 为什么必须重打 BOOT.bin（不能只换 .bit）

悟净板子的启动流程是 **FSBL 从 BOOT.bin 里加载 PL 位流**（不是 JTAG 烧的，也不是 `uEnv.txt` 的 `loadbit`——那份配置从 `mmc 0:2` 读 FAT，而 p2 是 ext4，实际不生效）。

所以：
- **旧 FSBL 里没有 bitstream 分区**，直接沿用旧 BOOT.bin → PL 里还是官方 demo 的位流，我们的 IP 根本没上板。
- 重打时**必须**让 FSBL 重新生成（SDK 会在 BIF 里有 `.bit` 项时把 bit 的处理逻辑编进 FSBL）。

---

## 2.1 ★ 位流 ≠ PS 配置：为什么"动态加载位流"这一步还不够

> 2026-10-26 S 板上实测后补：板子重启后跑的是官方位流（`/lib/firmware/bitstream.bin` 5,980,412 B），
> 跑 `pl_selftest.py` 直接 `Bus error`（exit=135）。原因有**两层**，必须分清。

| | 是什么 | 谁负责配置 |
|---|---|---|
| **PL 位流** | FPGA 内部逻辑（Top-Hat / CFAR / CCL / AXI 主机） | `bitstream.bin`，或 `fpga_manager` 动态加载 |
| **PS 侧接口（`ps7_init`）** | 各 AXI 主/从口是否使能、FCLK 频率、DDR/MIO 引脚 | **FSBL 里的 `ps7_init`**（来自 `.hdf`） |

我们的检测 IP 挂在 **`M_AXI_GP1`**、地址 **`0xA0000000`**：

| PS 接口 | 地址窗口 | 官方 FSBL 是否已开 |
|---|---|---|
| `M_AXI_GP0` | `0x4000_0000 – 0x7FFF_FFFF` | ✅ 开（官方 demo 用它接 AI_Mate 寄存器） |
| **`M_AXI_GP1`** | **`0x8000_0000 – 0xBFFF_FFFF`** | ❌ **没开** |
| `S_AXI_HP0 ~ HP3` | — | ✅ 开 |

⇒ **"位流加载成功 + `state=operating`" 只保证 PL 里有我们的逻辑；GP1 的时钟和地址窗口仍然关着**，
Python 一读 `0xA0000000` 就是 `Bus error`。这解释了 S 今晚的现象，也说明：

> **`.hdf` → 重打 BOOT.bin 仍然是必须的，但只是为了 `ps7_init` 那一小段（打开 GP1 + FCLK0=50 MHz），
> 不是为了打包位流。位流照样可以动态加载。**

### 2.1.1 判定表：Bus error 时先分清是哪一层

| 现象 | 结论 | 下一步 |
|---|---|---|
| `cat /sys/class/fpga_manager/fpga0/state` ≠ `operating` | 位流没加载进去 | 检查 `.bin` 格式 / 内核接口 |
| `state=operating`，但读 `0xA0000000` → **Bus error** | **GP1 没开**（当前 BOOT.bin 的 ps7_init 不含 GP1） | 等新 BOOT.bin，**不要**怀疑位流 |
| `state=operating`，能读但 `VERSION ≠ 0x00010000` | 位流是我们的但 PS 口没通 / 地址段错 | 查 Vivado 第 10 步地址分配与 `pl_link.py` 基址 |
| 读得到 `VERSION` 但 `STATUS` 一直 busy | 帧缓冲 / 触发时序问题 | 打 `status()` 的位域一起看 |

### 2.1.2 建议的验证顺序（避免白跑一轮）

1. **先验命令**：用**官方** `bitstream.bin` 跑一遍加载命令，确认能回到 `operating`
   → 证明命令与内核接口正确（不依赖我们的位流）。
2. **再换我们的** `ip2_board_top.bin`：若 `state=operating` 但仍 Bus error
   → 就是 GP1 没开，属预期，等新 BOOT.bin；**不必**再查位流格式。
3. **新 BOOT.bin 到位**：同一条命令再跑一次，`pl_selftest.py` 应打印 `VERSION = 0x00010000`。

> 应急备案（不推荐）：把 BD 改挂 **GP0**（地址落在 `0x4000_0000` 段）就能复用官方 `ps7_init` 立刻可用；
> 但该段被官方 AI_Mate 驱动占用（S 已验证 `0x40000000` 被禁止，设备树里也有节点），会冲突，
> 只在"必须今晚跑通"时考虑。

## 3. 打 BOOT.bin（SDK / Xilinx SDK 2018.2）

### 3.1 方式 A：用我们的 .hdf 新建（推荐，干净）

1. SDK → `File → New → Application Project`
   - Project name：`ip2_fsbl`
   - OS Platform：`standalone`，Processor：`ps7_cortexa9_0`
   - 勾 **Create New Board Support Package**（BSP 名 `ip2_fsbl_bsp`）
   - Target hardware：选 `ip2_bd.hdf`
2. 左侧 `ip2_fsbl` → 右键 → `New → Application Project` 里选 **Zynq FSBL** 模板
   （或：`File → New → Application Project`，模板页选 `Zynq FSBL`）
3. 写完 FSBL 后：`Xilinx → Create Boot Image`
   - **Boot image partitions**（顺序不能错）：

     | # | Partition | 说明 |
     |---|---|---|
     | 1 | `ip2_fsbl.elf` | 勾 **bootloader**（`[bootloader]` 前缀） |
     | 2 | `design_1.bit` | 从 `.hdf` 解出来的位流 |
     | 3 | `bl31.elf` | ATF（ARM Trusted Firmware），用官方的 |
     | 4 | `u-boot.elf` | 用官方的 |

   - Output BIF file：`ip2_ps.bif`（自动生成）
   - Output path：`ip2_ps\BOOT.bin`
4. 点 **Create Image**

> ⚠️ `bl31.elf` / `u-boot.elf` 用**官方参考包里那两份**（和现有板子能启动的一致），不要自己重编，除非要和 Linux 版本对齐。

### 3.2 方式 B：改官方 BIF（更快，但注意路径）

官方包 `D:\firstharness\dl\...`（或 S 手上的 `BOOT_Gen.rar`）里有 `7030ai_psin.bif`，内容形如：

```
the_ROM_image:
{
  [bootloader]FSBL251210_ddr400_demo.out
  ai7030_top_disable_icap.bit
  bl31.elf
  u-boot.elf
}
```

做法：复制一份改名 `ip2_ps.bif`，把**第 2 行的位流路径换成我们的** `design_1.bit`，第 1 行换成**新编的 FSBL**（官方那个 FSBL 不认识我们的 BD），再 `Xilinx → Create Boot Image` 用这个 BIF。

## 4. 上板

1. **备份现有 SD 卡里的 `BOOT.bin`**（改名 `BOOT_official.bak`，出问题能回滚）
2. 把新 `BOOT.bin` 拷到 SD 卡 **FAT 分区（第 1 个分区）的根目录**
   - Windows 下 SD 卡只有一个可见盘符就是 FAT 分区，直接复制覆盖
3. SD 卡插回板子 → 12V 上电 → 串口（115200 8N1）能看到 FSBL 日志
4. 启动后确认位流加载状态：

```bash
cat /sys/class/fpga_manager/fpga0/state     # 期望：operating
cat /sys/class/fpga_manager/fpga0/name      # 期望：显示我们的位流名
```

## 5. 第一次握手验收（关键一步）

```bash
sudo python3 pl_selftest.py
```

期望输出（关键行）：

```
[1] /dev/mem          OK
[2] udmabuf0          phys=0x30100000  size=134217728
[3] VERSION           = 0x00010000     ← 必须这一行对
[4] STATUS            = busy=0 done=0 error=0 n_cand=0 frame=0
```

判读表：

| 现象 | 含义 | 下一步 |
|---|---|---|
| `VERSION = 0x00010000` | **AXI 通路通了**，PS 能读写 PL 寄存器 | 进入相机/数据通路 |
| `VERSION = 0x00000000` 或 `0xFFFFFFFF` | 位流没加载 / BD 没接 / 地址错 | 查 `fpga_manager state`、查 `/proc/iomem` 有没有 `0xA0000000` |
| 打开 `/dev/mem` 报 `Permission denied` | 内核开了 `STRICT_DEVMEM` | 需要换内核配置或改用 udmabuf + DMA |
| `udmabuf0` 不存在 | 没加载 `u-dma-buf` 模块 | `modprobe u-dma-buf`，或在设备树里配 |

## 6. 兜底路径（BOOT.bin 打不出来时）

用 `fpga_manager` 直接加载 raw bin（不需要重打 BOOT.bin）：

```bash
# 1) P 侧应给出 ip2_board_top.bin（Procise: bitgen xxx.bin -g Binary）
sudo mkdir -p /lib/firmware
sudo cp ip2_board_top.bin /lib/firmware/
# 2) 触发重加载（不同内核路径不同，二选一）
sudo sh -c 'echo ip2_board_top.bin > /sys/class/fpga_manager/fpga0/firmware'
#   或
echo 1 | sudo tee /sys/class/fpga_manager/fpga0/flags
```

⚠️ **重要更正（2026-10-26）**：这条路径加载的是**纯 PL 位流，不含 `ps7_init`**。
虽然 BD 里我们没改 DDR/MIO，但**多开了一个 AXI 主口 `M_AXI_GP1`**，而官方 FSBL 的 `ps7_init`
只开 GP0 + HP0~3。所以**在当前 BOOT.bin 下，动态加载成功也访问不到 `0xA0000000`**（会 Bus error），
详见 §2.1。

⇒ 正确的用法：**动态加载只用于"快速换我们的位流做迭代"**，前提仍然是**先有一次用我们 `.hdf` 打出来的
BOOT.bin**（它把 GP1 + FCLK0=50 MHz 打开）。之后再迭代位流就不必反复重打 BOOT.bin 了。

## 7. 常见错误对照

| 报错/现象 | 原因 | 处理 |
|---|---|---|
| 串口停在 `FSBL` 无输出/反复重启 | BIF 里 FSBL 与 bit 不匹配 | 重打，确认 FSBL 是新建的 |
| 启动正常但 `fpga_manager` 目录不存在 | 内核没开 `CONFIG_FPGA_MGR_ZYNQ_FPGA` | 换官方内核镜像（官方镜像是开的） |
| `VERSION` 读到全 0 | PL 里跑的还是旧位流 | `cat /sys/class/fpga_manager/fpga0/name` 看名字 |
| `VERSION` 读全 0 且 `state=operating` | BD 地址段没分配上 | 回看 Vivado build 日志第 10 步有没有 `0xA0000000` |
| `devmem 0xA0000000 32` 段错误 | 该地址没映射（BD 没接 GP1 或地址错） | 同上 |
| `pl_selftest.py` 报 `Bus error`（exit=135），但 `state=operating` | **GP1 没开**：当前 BOOT.bin 的 `ps7_init` 不含 GP1 | 见 §2.1：需要新 `.hdf` → 重打 BOOT.bin |

## 8. 版本与回滚

- 位流与 BOOT.bin 都**带日期命名**：`BOOT_ip2_20261026.bin`、`design_1_20261026.bit`
- SD 卡上永远保留一份 `BOOT_official.bak`（官方可启动版），演示前确认能回滚
- 每次换位流，把 `VERSION` 的次版本号 +1（当前 `0x00010000`），方便确认板上跑的是哪一版
