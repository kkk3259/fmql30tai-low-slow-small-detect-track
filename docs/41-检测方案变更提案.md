# 检测方案变更提案：把"找目标"从 PL 形态学搬到 NPU YOLO

> 给 S / A 看的讨论稿。所有数字都是板上实测，不是估算。

## 一、现在的检测链路是怎么走的

```
USB 相机 640×480
   ↓ 裁上下 60 行
640×360 灰度
   ↓ 写 PL-DDR（512 位带宽）
【PL 检测器】Top-Hat 5×5/21×21 → CFAR 31×31 → CCL 连通域 → 候选表
   ↓ 候选表（x / y / 面积 / 峰值）
【PS 裁剪 128×128】→【NPU cls128 二分类】→ 判"是不是无人机"
   ↓
网页画框
```

**关键点：PL 干的是"找哪里有东西"，NPU 只干"这东西像不像无人机"。**

## 二、问题出在哪（实测数据）

### 问题 1：PL 的检测窗口被资源卡死，只有 2~4 像素

Top-Hat 用 SE×SE 的结构元做开运算，**任何比 SE 小的目标都会被抹掉**。窗口大小 = SE/2 左右。

三域位流（PS7+AI_Mate+检测器同板）的资源实测：

| SE | 检测窗口 | 三域 LUT 占用 | 能否装下 |
|---|---|---|---|
| 5 | 2~4 px | 84.4% | ✅ 当前用的 |
| 9 | 4~8 px | ~95.8% | ⚠️ 勉强（正在编） |
| 11 | 5~10 px | 98.4% | ❌ |
| 21 | 10~20 px | **114%** | ❌ 装不下 |
| 31 | 15~28 px | — | 只有"独立版"（不含 NPU）能到 |

**NPU 占了 41,830 个 LUT 当量，把检测窗口从 31 挤到了 5。**

### 问题 2：真实场景虚警高

合成剪影测试集（12 段）实测：召回 45.2% / 精确 76.6%。
拍显示器靶图：**0 个方块检出**（周围亮边框把 CFAR 的 31×31 局部均值和标准差抬高，方块落到门限以下）。

## 三、我提议的改动

**把"找目标"这一步整体搬到 NPU，用现成的无人机 YOLO11n。**

### 已经有现成模型（S 放在 `repo/deploy/`）

```
yolo11n_drone_trunc_ZG.raw    5.0 MB   无人机检测（YOLO11n，640×640）
yolo11n_drone_640x640.yaml
yolo11n_drone_int8.toml
```

### 我刚在板上实测（三域位流 + NPU）

```
NET_OK ops = 254                      ← 网络加载成功，254 个算子
APPLY_OK 4212 ms                      ← 一次性预加载
INPUT_SHAPE = [1, 640, 640, 3]        ← 输入 640×640×3
FORWARD_OK 4.31 ms   n_out=2          ← 单帧前向 4.31 毫秒
```

**4.31 ms 跑完一个 640×640 的 YOLO**，比我们 PL 检测器（4.19 ms）几乎一样快，但它**直接输出目标框**，不需要 PL 先找候选。

### 改完之后的链路

```
USB 相机 → 640×640 → 【NPU YOLO11n 4.31ms】→ 框 + 置信度 → NMS → 画框
```

PL 那套形态学可以：
- 方案 A：完全关掉（省 66K LUT，资源一下宽松）
- 方案 B：保留做"极小目标补充通道"（PL 只看 2~4 px，NPU 看常规尺寸）

## 四、需要和 S / A 确认的问题

1. **模型输出格式**：`n_out=2` 的两个输出 tensor 是什么布局？（YOLO11n 通常是 `[1,84,N]` 的预测 + 可能的 mask；需要确认具体 shape 和后处理方式）
2. **后处理在哪做**：NMS 应该在 PS 用 numpy 做（一帧几十个框，耗时 <1 ms）
3. **输入预处理**：模型要 640×640，我们相机是 640×360 —— 是 letterbox 补边还是直接拉伸？（影响坐标换算）
4. **NPU 独占问题**：我之前测 YOLO 时必须先停掉 `cam3d_pipe`，说明**同一时刻只能一个进程持有 NPU**。如果 PL 检测和 NPU 检测都要跑，需要合成一个进程
5. **模型泛化**：这个 YOLO 是无人机专训的，对非无人机目标（车、人、鸟）不会报框。演示非无人机场景要不要再挂 `yolov5s_352x640`（通用 80 类，也在板上，2.7 ms）
6. **精度未知**：我只验证了"能跑、4.31 ms"，**没有验证检测精度**（需要拿 `deploy/` 里那批带标注的样本跑一遍算 mAP）

## 五、两种方案对比

| | 现状（PL 找 + NPU 判） | 提案（NPU 直接找） |
|---|---|---|
| 检测窗口 | 2~4 px（S=5） | 模型学到的多尺度 |
| 单帧耗时 | PL 4.19 + NPU 1.9 = 6.1 ms | 4.31 ms |
| 需要候选 | 是（PL 先找） | 否 |
| 三域 LUT | 84.4%（PL 占 66K） | 平台 33.7K，**PL 可全空出来** |
| 虚警 | 纹理背景大量误报 | 有训练数据约束 |
| 风险 | 窗口受资源限制，改不动 | 精度未验证；模型只认无人机 |

## 六、要改的文件

| 文件 | 改动 |
|---|---|
| `ps/cam3d_pipe.py` | 检测环节从 `pl.run()` 换成 `yolo.forward()` + NMS |
| 新增 `ps/yolo_npu.py` | 封装加载/前向/后处理 |
| `ps/page_cam3d.py` | 框的标签从"面积/峰值"改成"置信度/类别" |
| 位流 | **不用改**（三域位流里 NPU 已经在，PL 检测器闲置即可） |

## 七、我的判断

如果 S/A 确认模型输出格式没问题，这条路的收益是：
- **检测能力从"2~4 px 专用"变成"训练集内任意尺寸"**
- **PL 资源全部释放**（以后想加什么都有地方）
- **链路更短**（少一次 PL 往返）

代价是：检测精度完全依赖这个模型的训练质量，而我们**还没验证过它的 mAP**。

**建议先做一件事**：用 `deploy/` 里那批带 `.txt` 标注的样本（我看到 `00008.jpg` + `00008.txt` 这种配对）跑一遍推理，算出召回/精确，再决定换不换。
