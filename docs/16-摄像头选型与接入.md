## 2. ⚠️⚠️ 三条强制采集参数（不照做一定出问题）

### ① 必须用 MJPG，不能用 YUY2

**板子只有 USB 2.0（480 Mbps 理论 / 约 40 MB/s 实际），4 个口还共享一个 USB2514 HUB。**

| 格式 | 1280×720@30 | 1920×1080@30 |
|---|---|---|
| **MJPG** | 约 15~25 Mbps ✅ | 约 30~50 Mbps ✅ |
| YUY2（未压缩） | 1280×720×2×30 = **442 Mbps** ❌ 超带宽 | 995 Mbps ❌ 远超 |

**官方帧率表也印证：1080P 下 YUY2 只有 5 fps，MJPG 才能 30 fps。**

### ② 采集分辨率用 **1280×720**，不要用 1920×1080

**原因：PS 侧传统 CV 算法固定吃 640×360。**

```python
# baseline/run.py:to_gray_down
gray = cv2.cvtColor(frame_bgr, cv2.COLOR_BGR2GRAY)
gray = gray[::down, ::down]        # down=2，直接切片取每 2×2 块左上角

# 1280×720 ÷ 2 = 640×360   ✅ 尺寸完全对上，算法参数一个字都不用改
# 1920×1080 ÷ 2 = 960×540  ❌ 尺寸不对，Top-Hat/CFAR/候选表/PL 全要重算
```

**⇒ 用 1280×720，整条链路零改动。**

### ③ 必须关闭自动曝光（AEC）

**场景是「亮天空背景 + 暗小目标」。自动曝光盯着天空调，会把地面目标压成一片黑。**

```bash
v4l2-ctl -d /dev/video0 --set-ctrl=exposure_auto=1           # 1 = 手动模式
v4l2-ctl -d /dev/video0 --set-ctrl=exposure_absolute=100     # 具体值现场调
v4l2-ctl -d /dev/video0 --set-ctrl=gain=0                    # 增益也固定住
```

**⚠️ 曝光值需要现场标定：先在目标场景下让自动曝光跑 3 秒，读回 `exposure_absolute` 的值，再锁定。**

## 3. 三种调用方式

### 3.1 v4l2-ctl（调试 / 参数设置）

```bash
# 看支持哪些格式（★ 到货第一件事）
v4l2-ctl --list-formats-ext -d /dev/video0

# 看有哪些可调控制项（★ 确认曝光能手动）
v4l2-ctl --list-ctrls -d /dev/video0 | grep -iE "exposure|gain|white"

# 锁定采集格式（部分场景需要显式设置）
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1280,height=720,pixelformat=MJPG
v4l2-ctl -d /dev/video0 --set-parm=30
```

### 3.2 ffmpeg（抓单帧 / 推流 / 存视频）

```bash
# 抓一帧验证画面
ffmpeg -f v4l2 -input_format mjpeg -video_size 1280x720 -framerate 30 \
       -i /dev/video0 -frames:v 1 /root/cam_test.jpg

# 录 10 秒视频（做演示素材）
ffmpeg -f v4l2 -input_format mjpeg -video_size 1280x720 -framerate 30 \
       -i /dev/video0 -t 10 -c:v copy /root/cam_record.mp4
```

**⚠️ `-input_format mjpeg` 必须显式写，否则 ffmpeg 可能协商成 YUYV → 掉到 9 fps。**

### 3.3 OpenCV（PS 侧集成，⭐ 最终用法）

```python
import cv2

cap = cv2.VideoCapture(0)                       # 摄像头设备号
cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*'MJPG'))   # ★ 必须，否则 9 fps
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 1280)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 720)
cap.set(cv2.CAP_PROP_FPS, 30)
cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)             # ★ 只留 1 帧缓冲，降低延迟

ok, frame = cap.read()
assert ok and frame.shape == (720, 1280, 3), frame.shape
```

**⚠️ OpenCV 的顺序有讲究：`FOURCC` 要在设分辨率**之前**，否则可能被重置。**

## 5. ⚠️ 与两套算法的对接点（**最容易出错的地方**）

**本项目有两条 AI 路径，对输入尺寸的要求**不同**：**

| 路径 | 输入要求 | 摄像头 1280×720 怎么变过去 |
|---|---|---|
| **传统 CV**（`ps/ps_app.py`）| **640×360**（16:9）| `gray[::2, ::2]` 直接降采样 ✅ **零改动** |
| **YOLOv11n**（NPU）| **640×640**（1:1）| ⚠️ **不能直接 resize**，16:9 → 1:1 会横向压扁 |

**⇒ YOLO 路径必须做 letterbox（保持宽高比 + 上下补边）：**

```python
def letterbox(img, dst=640):
    h, w = img.shape[:2]
    scale = min(dst / w, dst / h)
    nw, nh = int(w * scale), int(h * scale)
    resized = cv2.resize(img, (nw, nh), interpolation=cv2.INTER_LINEAR)
    canvas = np.zeros((dst, dst, 3), dtype=np.uint8)
    top, left = (dst - nh) // 2, (dst - nw) // 2
    canvas[top:top+nh, left:left+nw] = resized
    return canvas, scale, left, top        # 后处理要把框映射回原图坐标
```

**⚠️ 后处理必须用 `scale / left / top` 把检测框反算回原图坐标，否则画出来的框位置全错。**

**⇒ 这是 A 的模型上视频时最容易出错的一步，建议先用 A 的 `deploy/cpu_decode_demo.py` 对拍验证。**

## 7. 风险与备选

| 风险 | 概率 | 应对 |
|---|---|---|
| **板上内核缺 `uvcvideo` 驱动** | 低 | 板子跑 Ubuntu 20.04 标准内核，一般自带；`lsmod \| grep uvc` 确认，缺则 `modprobe uvcvideo` |
| **MJPG 帧率达不到 30** | 低 | 先降 720P → 640×480@30 确认链路，再逐步提高；或换 USB 口（4 个口共享 HUB，尽量只插摄像头）|
| **曝光控制项缺失（固件不下发）** | 中 | 联系商家要固件；或用 `v4l2-ctl --set-ctrls` 尝试 `exposure_auto_priority`；最差退回自动曝光 + 后处理非线性拉伸 |
| **画面偏紫/偏色** | 低 | 说明 IR-cut 滤镜不对，联系商家换 650 nm 版本 |
| **USB 带宽竞争** | 中 | 演示时拔掉其他 USB 设备；必要时把串口改走 UART 口而非 USB |

## 8. 与项目其他模块的关系

| 模块 | 影响 |
|---|---|
| **PS（S）** | 输入源从 `cv2.VideoCapture("bird.mp4")` 换成 `cv2.VideoCapture(0)`，其余零改动（传统 CV 路径）|
| **模型（A）** | YOLO 路径需加 letterbox（见 §5）；输入尺寸仍为 640×640，模型不用改 |
| **PL（P）** | **无影响**。PL 从 `/dev/udmabuf0` 取灰度帧，不直接接触摄像头；摄像头由 PS 负责采集后写入 udmabuf |
| **NPU** | 无影响。NPU 吃的是 PS 送来的张量，不关心数据来自摄像头还是文件 |

**⚠️ 因此在摄像头到货前，整条链路可以完全用 `/root/bird.mp4`、`/root/synth_sky.mp4` 推进，不会卡住任何模块。**
