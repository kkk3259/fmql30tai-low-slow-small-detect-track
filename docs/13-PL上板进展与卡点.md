## 四、我现在卡在哪 / 需要你们（S）给的东西

### 卡点 1（最高优先级）：位流怎么进板

现状：板子从 SD 卡启动，`/sys/class/fpga_manager/fpga0/state = operating` 是 **BOOT.bin 内嵌官方位流、FSBL 启动时加载**的结果（你分析得对，`uEnv.txt` 里的 `loadbit` 那条实际不生效）。

我们要换成自己的位流，三条路，**请确认哪条可行、以及谁来操作**：

1. **Linux 里用 fpga_manager 加载**：需要 **raw `.bin`**（Xilinx 格式：去掉 .bit 头）。请确认：内核有没有 `fpga_manager` 的 xilinx/fmsh driver、`/sys/class/fpga_manager/fpga0/firmware` 能不能直接 `echo xxx.bin > firmware`，以及 `/lib/firmware` 在不在。
2. **u-boot `fpga loadb`**：需要位流放在 p1（FAT）里。请确认 p1/p2 分区布局、`boot.scr`/`uEnv.txt` 是不是你们能改的。
3. **重打 BOOT.bin**：官方包里有 `BOOT_Gen.rar`。请确认 FSBL 是哪一个、能不能把我们的 `.bit` 替换进去重新打包。

> ✅ **已查到结论（不用等）**：Procise 的 `bitgen` 支持 `-g Binary`，直接输出 `xxx.bin`。
> 《Procise 用户使用手册》原话："生成 binary 文件（design_name.bin），该文件中**只包含用于配置 fpga 的位流信息，不包含用于下载的头信息**"。
> 这正是 Linux `fpga_manager` 和 u-boot `fpga loadb` 需要的 raw 格式 → **我们这边能直接产 `.bin`**，
> 只要你们告诉我往哪放、怎么触发（`/lib/firmware` + `echo xxx.bin > .../firmware`？还是 p1 分区 + `fpga loadb`？）。

### 卡点 2：PS↔PL 数据通路（这是我接下来一个月的主战场，需要你先定接口）

我的 IP2 现在是**纯流式核**：`i_data[7:0] + i_valid + i_ready → o_data[7:0] + o_valid`，**没有任何 AXI 接口**。要接到 detect 里必须二选一：

- **A. AXI4-Stream + DMA**（推荐，吞吐高）：PL 侧包一层 AXI4-Stream，PS 侧用 AXI DMA（或你们的 CDMA）把一帧 DDR 数据推给 PL，接收端收回 36 字节候选表。
- **B. AXI4-Lite 寄存器 + PL 直接读 DDR**：PL 侧做 AXI Master 读帧、写结果。

**需要你给我的接口约定**（缺一个我都写不了）：

1. 输入帧在 DDR 的**物理地址/怎么分配**（CMA？`/dev/mem`？dma-buf？），一帧多少字节
2. 输入格式：灰度还是彩色？行列序？stride？640×360 还是 1280×720
3. 谁触发一帧（寄存器写 1？中断？polling？），输出（36 字节）放在哪、怎么通知 PS 取
4. PS 侧 detect 的**算法参数**：✅ 已对齐（S 确认 `win=31 / k=4.0 / floor=3.0 / min-area=2 / max-area=200 / topk=5 / down=2`；硬件已从 MAD 近似改为**真实 std**，判决用平方比较 `L² > k²(A·S2−S1²)`，不开方）
5. AXI 时钟：你说的 GP/HP 接口设计最高 **100 MHz** —— 我们主频正好 100 MHz，可以直接对上（如果你们要 150/200 MHz，我要改约束重跑时序）

### 卡点 3：摄像头

板载接口是 **MIPI CSI（J16，15 pin FPC）**。请确认两件事：

1. 你们手上的摄像头是 **MIPI 模组**还是 **USB(UVC)**？
2. 如果是 MIPI：PS 侧有 CSI 驱动吗？PL 侧要不要做 ISP（Bayer→RGB / 去马赛克）？—— 如果要，这是另一个大工程（至少 1~2 周），**建议先用 USB 摄像头或离线视频跑通链路**，MIPI 后面再上。
