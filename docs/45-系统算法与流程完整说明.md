# 低小慢目标检测系统 · 算法与流程完整说明

> 2026 全国大学生嵌入式芯片与系统设计竞赛（FPGA 赛道）
> 板卡：FMQL30TAI676HM（悟净 Lite，复旦微 FMQL7030 ≈ Xilinx Zynq-7000 `xc7z030ffg676-2`）
> 文档版本：v1.0　对应位流 `ours3d_s5`（WNS +0.030 ns）

---

## 1. 系统总览

### 1.1 三域分工原则

| 域 | 职责 | 特点 |
|---|---|---|
| **PL（可编程逻辑）** | 逐像素无分支流式粗筛：Top-Hat → CFAR → 连通域 → 候选表 | 确定性延迟 4.2 ms/帧，不看内容只看局部亮度统计 |
| **NPU（AI_Mate）** | 语义精判：对候选 ROI 放大后跑 YOLO11n 判"是不是无人机" | 4.24 ms/次前向，一次可判 16 个 ROI（mosaic） |
| **PS（ARM）** | 调度、坐标融合、跟踪、编码、网页推流 | 采集 23 ms、编码 27~38 ms |

一句话：**PL 负责"便宜地筛掉 99.99% 的像素"，NPU 负责"认得出"，PS 负责"想得清"。**

### 1.2 为什么必须这样分工

- 整帧 640×360 直接送 YOLO（640×640 输入）时，1280×720 画面里 20 px 的无人机缩到 640 只剩 **10 px**，低于 YOLOv8 有效感受野（32~320 px）下限 → 必失效。
- PL 先出候选 → PS 裁 96×96 → 放大到 160 格 → 等效 **3.3 倍**放大（20 px → 66 px）→ 落回模型有效区。
- 反之若完全靠 NPU 做粗筛，整帧推理 26 ms/帧且小目标漏检；完全靠 PL 则虚警高、分不清类别。

## 3. PL 检测器算法

### 3.1 流水线结构

```
512 位 PL-DDR 行流
      ↓  适配层 ip2_user_op.v（一行一个 AR，地址 +64）
   win5.v  5×5 窗口（4 条行缓存 + 5 个行抽头，minmax 树）
      ↓
tophat_5x5_stream.v  Top-Hat：原图 − 开运算(SE=31)
      ↓               （先腐蚀 min，再膨胀 max，SE 可参数化）
cfar_threshold_stream.v  CFAR：31×31 局部统计 + MAD 判据
      ↓
candidate_extract_stream.v  连通域标记 + 并查集 + 质心/面积/峰值
      ↓
   候选表（1 + 64×7 = 449 字节）
```

### 3.2 Top-Hat（顶帽变换）

**定义**：`TopHat = 原图 − 开运算(原图, SE)`

- 开运算 = 先腐蚀（取 SE 内最小值）再膨胀（取 SE 内最大值）
- 效果：**抹掉比 SE 小的亮块**，保留"比 SE 小"的亮目标，去掉大面积背景
- SE 尺寸决定检测窗口：SE=31 时可检测 **6~28 px** 的目标（实测）

**RTL 实现**：
- `win5.v` 用 4 条行缓存（每条 640×8 位）+ 5 个行抽头构造 5×5 窗口
- 31×31 的 min/max 用**两级平衡树**（`minmax_tree.v`），10 级逻辑
  - 曾经用 441 抽头线性比较链 → 60 级逻辑 → WNS −7.775 ns
  - 改平衡树后 WNS +1.444 ns

### 3.3 CFAR（恒虚警率检测）

**判据**（不用除法、不开方）：

```
像素 x 满足：  x > μ + k·σ + floor
等价于：       L² > k²·(A·S2 − S1²)
其中：         A  = 有效窗面积
              S1 = Σx   （局部和）
              S2 = Σx²  （局部平方和）
              L  = x·A − S1 − floor·A
```

**为什么这样变形**：`σ = sqrt((A·S2 − S1²)/A²)`，两边平方后开方和除法都消掉了，只剩乘法和比较。位宽：

| 量 | 位宽 |
|---|---|
| S1 | 18 |
| S2 | 26 |
| A·S2 | 37 |
| S1² | 36 |
| L | 20 |
| L² | 38 |
| k² | 16（k=4 时就是左移 4 位） |

**流式实现**（关键设计）：
- 滑动窗口 O(1) 求和：31 行延迟线 + `col_sum` 累加器 + 31 项 fifo + 31 输入加法树
- 两遍扫描：第一遍算均值存 `img_bram` + `mean_bram`，第二遍算 MAD
- **居中窗口**：`col_sum` 加宽到 `W+15`，列计数器在 `W+14` 回绕，用 `ccnt`/`cflat` 做虚拟→图像坐标映射，`DELAY_D = 31×(W+15)`
  - 这样输出覆盖全 N 个像素，**没有死区**
- 实测一致性：64×64 差 4 个像素（0.1%）、128×72 差 2 个（0.02%）

### 3.4 CCL（连通域标记）

**单趟扫描 + 并查集**：

```
按行主序逐个像素：
  若 bin=1：
    看左邻和上邻的标签
    都没有 → 新标签
    只有一个 → 继承
    两个不同 → 合并（并查集 path halving）
     同时即时累加该标签的 Σx、Σy、Σ1（质心与面积）
扫描完 → S_MERGE 按标签降序单拍并父 → S_POST 串行算质心
```

**关键参数**：8 连通，`MAX_COMP = 64`，`MAX_CAND = 8`，面积过滤 `MIN_AREA=2 / MAX_AREA=2047`

**踩过的坑**：
- `n_comp` 用 NBA 循环递增 → 改成组合逻辑计数器
- 排序位宽 4 位溢出 → `sj` 扩到 7 位、`mi` 扩到 6 位
- 质心累加器 16 位溢出（16 px 目标 x 报成 48 而不是 320）→ 改 24 位累加 + 16 位除数
- `S_POST` 里 `for (i=0;i<64;i=i+1)` 被完全展开成 128 个 16 位除法器 → LUT 104,950；改 `reg [6:0] pi` 串行 → LUT 降到 37,157（−64%）

### 3.5 候选表格式

每帧输出 `1 + MAX_CAND×7` 字节：

```
byte 0     : n_cand
每个候选 7 字节：x_hi, x_lo, y_hi, y_lo, area_hi, area_lo, peak
```

坐标是**质心**，按峰值降序排列。

## 4. PS 侧处理流程

### 4.1 主循环

```
1. 采集 640×480 → 裁 640×360 → 灰度
2. （可选）gamma 校正：out = 255·(x/255)^γ，γ<1 抬亮暗部、压缩背景动态范围
3. 写 PL-DDR（230,400 字节）
4. 触发 PL 检测（写 CTRL.start）
5. 轮询 STATUS：等 AR 增长 > 3000 且 busy=0（**必须等 busy=0**，否则读到写了一半的旧表）
6. 读候选表 → 列相位修正 → 边界过滤 → 按峰值排序取前 16
7. 双极性：对 255−gray 再跑一遍，两种极性各取前 8（**不能混排**，否则一路的虚警挤掉另一路的真目标）
8. 每个候选裁 96×96 → mosaic 拼 2×2/4×4 画布 → NPU 一次前向
9. 解码 + NMS + 去重（半径自适应 `max(18, min(0.55·w, 60))`，保留高分框）
10. 跟踪（质心关联 + EMA + 迟滞）→ 画框 → MJPEG 推流
```

### 4.2 双极性为什么必要

- Top-Hat 只对**亮目标**敏感（白帽），暗目标要靠反极性（黑帽）
- 三域 LUT 84.4% 装不下两份检测器 → **同一个检测器跑两遍**（正常灰度 + 取反灰度），零额外 LUT，只花时间
- 实测：鸟视频单极性 hit 0.09/帧 → 双极性 0.21/帧（提升 2.3×）

### 4.3 gamma 预处理（最大的单一算法收益）

```
γ=1.0  → 召回 9.0% / 精确 0.9%
γ=0.08 → 召回 45.2% / 精确 76.6%
```

原理：γ<1 把暗部整体抬亮，**压缩背景动态范围** → CFAR 的局部 σ 变小 → 门限降低 → 弱目标显示出来。

### 4.4 列相位问题（已知缺陷）

- **现象**：检测出的 x 坐标整幅偏移 0 或 ~62 px，同一进程内固定，重启后可能翻转
- **推断根因**：适配层 `ip2_user_op.v` 没有帧级清 FIFO，上一帧尾部残留 64 字节（=64 像素）会顺延到下一帧
- **当前处理**：软件加固定 `+62` 修正（`offline_*` 系列脚本）
- **待办**：适配层加 `frame_clr`，或在启动时用真实帧校准一次

## 5. NPU 精判

### 5.1 模型

| 项 | 值 |
|---|---|
| 模型 | `yolo11n_drone_trunc_ZG`（A 提供） |
| 输入 | `[1, 640, 640, 3]` NHWC uint8（letterbox，灰底 114） |
| 输出 | `OUT0 [1, 64, 8400]` + `OUT1 [1, 1, 8400]` |
| 意义 | 8400 = 80²+40²+20²（stride 8/16/32），64 = 4 框 + 60 类 |
| 精度 | int8 量化，步长 0.8066（所以分数只有 0.50/0.69/0.83/0.92 几档） |
| 耗时 | **forward 4.24 ms**；含预处理与解码约 26~31 ms |

### 5.2 解码（anchor-free，YOLOv8 距离式）

```python
score = sigmoid(out1) * max(sigmoid(out0[4:]))     # 先取类最大 logit 再 sigmoid（等价且快 15 倍）
l, t, r, b = a[0]*4, a[1]*4, a[2]*4, a[3]*4        # 单位 stride
x1 = (gx + 0.5 - l) * st;   y1 = (gy + 0.5 - t) * st
x2 = (gx + 0.5 + r) * st;   y2 = (gy + 0.5 + b) * st
```

**必须做 letterbox 而不是拉伸**：拉伸把 640×360 纵向放大 1.78 倍，实测同一帧 top 分数从 0.689 掉到 0.308、框数 11 → 0。

### 5.3 mosaic 批处理

把 N 个 96×96 裁片按 2×2 或 4×4 拼进 640×640 画布（cell = 640//grid，等比缩放居中、114 灰底），一次前向判全部，再按格中心把框回映到原图坐标。

实测（t4 四架手工裁 4 块 96×96）：

```
grid=4  n=4  43.5 ms   四架全中（83% / 83% / 69% / 66%）
grid=2  n=8  53.3 ms
```

### 5.4 一个关键坑：Device 独占

`PL3D` 与 `Yolo()` **各自 `Device.Open`** 时，icraft 后注册的会接管 DMA 区域 → `pl: Write failed at AXIZG330AIUdmaMemRegionNode::write`。

**修法**：`Yolo.__init__(self, dev=None)` 复用调用方的 Device：`YOLO = Yolo(dev=pl.dev)`。

### 6.1 跟踪器

```python
MATCH_R   = 12      # 关联半径（px）
MIN_HITS  = 2       # 连续命中几帧才确认
MAX_MISS  = 10      # 连续丢失几帧才删除
```

- 质心最近邻关联
- 速度 EMA 平滑，用于显示速度与预测

### 6.2 显示

| 颜色 | 含义 |
|---|---|
| 绿粗框 | 已确认航迹 **且** NPU 判为无人机（p ≥ 50%） |
| 橙粗框 | 已确认航迹但 NPU 判不是（p < 50%） |
| 灰细框 | 单帧瞬时候选（未确认） |
| 黄色轨迹线 | 该航迹最近 N 帧的位置连线 |

HUD 与标签全部由 canvas **矢量绘制**（不烧进 JPEG），标签显示百分比。

### 6.3 帧率优化

| 手段 | 效果 |
|---|---|
| 采集/推理/编码三线程 | 15 → 26.4 fps |
| 整帧 yolo 隔帧推理（`YOLO_EVERY=2`，复用上次框） | 19.6 → **29.8 fps** |

| `sync_size` 128 MiB → 230400 | PL 23.5 → 11.7 ms |

## 8. 已知限制（诚实记录）

| 限制 | 表现 | 原因 |
|---|---|---|
| **强纹理背景失效** | 鸟飞过白云时 PL 抓不到 | 云的局部 σ 把 CFAR 门限抬高，目标被背景淹没 |
| **大目标超窗口** | t4 四架 40~90 px 只出 1 框 | Top-Hat SE=31 的检测窗口是 6~28 px，超出即被当背景抹掉 |
| **列相位不稳** | x 偏移 0 或 ~62 px | 适配层缺帧级清 FIFO |
| **虚警** | 云边、水面反光、飞机机身被认成目标 | PL 只看局部亮度；NPU 模型领域偏窄 |
| **机体过小** | 1280×720 里 10 px 的目标 | 低于 YOLO 有效感受野 |
| **阈值量化** | 0.45/0.55 之间整批跳变 | int8 量化，分数只有四档 |

## 10. 关键寄存器

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x00 | CTRL | bit0 = start（写 1 触发一帧） |
| 0x04 | FRAME_ADDR | 帧数据物理地址（0x30100000） |
| 0x08 | RESULT_ADDR | 结果区地址 |
| 0x0C | STATUS | bit0 busy / bit1 done / bit2 err / [15:8] n_cand / [23:16] frame_cnt |
| 0x14 | VERSION | 0x00010000（探活用） |
| 0x18~0x38 | 候选表兼容视图 | 9 个 32 位字 = 36 字节 |

> **只读这些地址**。读未实现的地址会让 PL 不回 rvalid → PS 永久卡死 → 只能断电。

## 11. 教训清单（给后来的自己）

1. **不要在进程持有 PL 时重配位流** —— PS 停在等 AXI 响应，只能断电。
2. **读候选表前必须等 busy=0** —— 否则读到写了一半的上一帧。
3. **双极性候选不能混排取 top-N** —— 一路虚警会挤掉另一路真目标，必须各取前 N。
4. **letterbox 不是可选项** —— 拉伸会让分数从 0.69 掉到 0.31。
5. **`global` 声明漏一个名字就是一个 bug** —— 本项目栽过三次（`GAMMA`、`USE_YOLO`、`YOLO`），而且日志看不出来。
6. **每个候选都调一次 NPU 会很慢** —— mosaic 一次判 16 个。
7. **改了参数必须重跑同一张图六次** —— 否则分不清"改进"和"运气"。
