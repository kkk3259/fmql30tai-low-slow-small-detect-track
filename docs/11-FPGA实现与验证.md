## 1 PL 在系统中的角色

本系统采用三层异构架构：**PS** 做采集/调度/跟踪（控制面），**PL** 做像素级数据面运算，**NPU** 做 ROI 精判别。

PL（FPGA）承担链路中**数据量大、逻辑规则固定**的三段像素级运算：

```
彩色帧 ──▶ [IP1 预处理] ──▶ [IP2 增强+检测] ──▶ [IP3 后处理] ──▶ 候选列表 ──▶ NPU/PS
          灰度+降采样      Top-Hat→CFAR→CCL      ×2+NMS
```

## 2 模块划分与实现

| IP | 文件 | 功能 | 关键实现 |
|---|---|---|---|
| **IP1** | `preproc_axis.v` | 彩色(BGR)→灰度 + 2×降采样 | 14 位定点 BT.601，**无高斯**（见 D1） |
| **IP2-①** | `tophat_5x5.v` | 5×5 形态学 Top-Hat | 纯 min/max 比较，无乘法 |
| **IP2-②** | `cfar_threshold.v` | 31×31 自适应阈值 | **定点 MAD + 积分图滑动盒式滤波（O(1)）** |
| **IP2-③** | `candidate_extract.v` | 连通域标记(CCL) + 候选提取 | 8 连通 BFS 洪泛 + 质心/面积/峰值 |
| **IP2 顶** | `ip2_top.v` | 三段串联整合 | Top-Hat → CFAR → CCL |
| **IP3** | `postproc_axis.v` | 非极大值抑制(NMS) | 合并过近候选（矩形邻域），输出降采样坐标 |
| **IP4** | `roi_pack.v` | 裁 ROI 打包 | 按候选裁 128×128 ROI（越界补 0），I3 接口 |

### 2.1 IP1 预处理：14 位定点灰度化（0 误差）

灰度化对齐 OpenCV BT.601，用 14 位定点避免 8 位系数截断误差：

```
gray = (4899·R + 9617·G + 1868·B + 8192) >> 14
```

8 位系数版（`(77R+150G+29B)>>8`）与 OpenCV 存在 **28/256 像素的 1 LSB 误差**；
改用 14 位精确系数后，**与 `cv2.cvtColor` 逐像素 0 误差**。

### 2.2 IP2-② CFAR：定点 MAD + 积分图（可综合 + O(1)）

这是 PL 的核心难点，做了两层优化：

1. **定点化**：把浮点 `mean + 4.0×std + 3` 改为整数 **`mean + 5×MAD + 3`**（MAD=平均绝对偏差 ≈ 0.8×std，故 k 由 4.0 调 5）。**避开开方 `$sqrt`**，完全可综合；
2. **积分图滑动盒式滤波**：31×31 窗口求和从 O(961) 降到 **O(1)**（4 次查表 + 3 次加减），640×360 也可实时。

边界采用**裁剪窗口**（窗口在图像边缘自然缩小、按实际像素数求均值）——比"复制边缘"更省硬件，是 FPGA 常见做法。

### 2.3 IP2-③ 候选提取：8 连通 CCL

二值图 → 8 连通域 BFS 洪泛 → 每个连通域算**质心/面积/峰值** → 按峰值降序取 top 8。

质心与软件严格对齐：`centroid = (sum_x + area/2) / area`。

### 2.4 IP3 后处理：NMS

- NMS 合并过近候选（矩形邻域 `|dx|≤3 && |dy|≤3`，免乘法）；
- **坐标保持降采样坐标（不 ×2）**——I2 约定 ×2 由 PS 显示时做；
- **坐标 16 位**输出，支持 640×360（坐标 0~639，超出 8 位上限 255）。

### 2.5 IP4 ROI 打包：裁 128×128

- 按候选中心 `(cx,cy)` 裁 **128×128** ROI（左上角 `(cx−64, cy−64)`），**越界补 0**；
- 对齐 `ps_app.py::crop_roi`，对应接口 **I3**（`roi_data[128][128]` + `offset_x/y`）；
- 语义简单、无乘法，逐字节验证通过。

## 3 定点化方案总表

| 环节 | 定点方案 | 依据 |
|---|---|---|
| 灰度化 | `(4899R+9617G+1868B+8192)>>14` | 14 位对齐 OpenCV BT.601，0 误差 |
| Top-Hat | 纯 min/max | 形态学无乘法 |
| CFAR | 整数 MAD：`mean+5×MAD+3` | 避开 sqrt，可综合；MAD≈0.8×std |
| 质心 | `(sum+area/2)/area` | 四舍五入对齐 Python 整除 |
| 坐标 | 16 位无符号 | 支持 640×360 |

## 4 验证方法：软硬件协同验证

板卡未到，采用**"以软验硬"**：每个模块配套 Testbench + OpenCV 参考值，仿真阶段逐像素/逐字段自动比对。

统一 4 步（任何模块都一样）：

```
① Python 生成激励 + OpenCV 参考  → ② iverilog 编译  → ③ vvp 仿真  → ④ 逐像素/字段比对
```

- 所有 testbench 带**文件检查**（激励缺失立即报错，不静默跑假结果）；
- 带**反压测试**（随机 `o_ready` 验证握手不丢数据）；
- 固定随机种子，脚本入库、产物不入库，可复现。

## 6 关键设计决策与创新点

| # | 决策/创新 | 说明 |
|---|---|---|
| 1 | **关闭 3×3 高斯** | 高斯专门打击半径 ≤1.5px 的小目标（Pd −45.7 点），而小目标正是本课题目标 |
| 2 | **CFAR 定点 MAD + 积分图** | 避开开方、可综合；盒求和 O(1)，640×360 可实时 |
| 3 | **16 位坐标** | 支持 640×360，避免 8 位坐标溢出 |
| 4 | **非 2 幂宽度支持** | 行列索引用真除法/取余，而非位切片——修复了 320/640 宽度的隐藏 bug |
| 5 | **14 位精确灰度化** | 比 8 位系数多 1 LSB 精度，做到 0 误差 |

## 7 已知差异（如实注明）

1. **边界处理**：积分图 CFAR 用"裁剪窗口"（边缘窗口变小），与 OpenCV 的 `REFLECT_101` 仅最外一圈不同；目标均置于内部，不影响检测；
2. **MAD 近似 std**：资源-精度取舍，系数 k 由 4.0 调 5；
3. **并列排序**：peak 相同时候选排列顺序未定义（不影响检测正确性，比对时按"峰值→x→y"规范排序）。

## 8 性能估算（640×360）

全链约 14N ≈ 3.2 M 时钟周期：

| PL 时钟 | 每帧耗时 | 帧率 |
|---|---|---|
| 100 MHz | ~32 ms | 31 fps |
| 150 MHz | ~21 ms | 47 fps |

相机为 720P30，**PL 处理不是瓶颈**。

## 10 后续优化方向（备忘，供后续加分）

**时域增强模块**（S 提议，软件实测候选 −75%、虚警 −95%、跟踪成功率持平）：
- 原理：帧缓存 N 帧 → 按速度参数**整数移位对齐**（PL 免费，移位是硬件强项，免插值/浮点）→ 累加求平均；
- **待定：帧缓存放哪**——一帧 640×360×8bit = 1.84 Mbit，N=16 需 29.5 Mbit > 板卡 PL 的 9.3 Mbit BRAM，放不下。候选方案：① 帧缓存放 DDR（PS 侧，数据来回搬，PL 优势打折）；② 减小 N（N=4 约 7.4 Mbit，仍顶格）；③ 帧缓存用降采样图。**等流水线化做完、BRAM 预算清楚后再定**，别与流水线化抢 BRAM。
