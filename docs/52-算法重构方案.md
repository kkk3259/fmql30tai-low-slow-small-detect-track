# 低小慢目标检测 · 算法重构方案

> 目标：在 xc7z030（78,600 LUT / 265 BRAM / 400 DSP）上重做 PL 粗筛，
> 让“摄像头 → PS 解码 → PL 粗筛+裁剪(128) → NPU 二分类 → PS 跟踪 → 输出”
> 这条链路真正跑出效果。不参考现有实现。

---

## 一、现有实现为什么差（实测归因）

| 现象 | 实测数据 | 根因 |
|---|---|---|
| 一个目标出左右两个框 | `(394,213,a1146)` 与 `(504,214,a314)`，x 差 110 | Top-Hat 的 SE=5 远小于目标尺寸，内部被开运算抹平，只剩左右边带；两条边带不连通，CCL 无法合并 |
| 每帧 5~7 个候选，多是虚警 | 真目标 area 550~1146 / peak 206~212；虚警 area 17~250 / peak 10~127 | RTL 门限 `MIN_AREA=2` 过低；且 CFAR 无法区分“点目标”与“建筑边缘” |
| 6~20 px 目标检不到 | 检测窗口仅 1~4 px | SE=5 太小，大于 SE 的目标只剩边缘 |
| 纹理背景（草/海/夜）候选恒为 0 | 5 个场景全部 0 | CFAR 用 31×31 局部 σ，纹理把 σ 抬高 → 门限超过目标 |
| NPU 判别无输出 | 端到端 TP=0 | 候选里大部分是杂波，NPU 看到的是“杂波裁片” |

**一句话：现在的 PL 是“找亮点”，不是“找目标”。** 只要比周围亮就被选出来，
不区分“点状目标”和“线状边缘”。

## 二、新链路设计

```
PS：摄像头 → 裁 640×360 灰度 → 写 DDR
        ↓
PL（全流式，逐像素，无分支无除法）
   ① 多尺度 Top-Hat        SE = 5 / 9 / 15 三路并行，逐像素取 max
   ② 局部对比度 LCM        中心 5×5 vs 8 方向 5×5，取 min 比值
   ③ 双门限              局部自适应（小窗）+ 全局 Top-K
   ④ CCL + 形状过滤       面积 / 长宽比 / 填充率
   ⑤ 排序输出             按 (对比度 × √面积) 降序，≤16 个
        ↓
PS：⑥ 自适应裁剪（边长 max(48,4√area) ≤128）
   ⑦ mosaic 拼 4×4 → cls128 二分类（0.27ms/次）
   ⑧ 卡尔曼滤波 + 匈牙利匹配跟踪
   ⑨ 绿框（p≥0.5 且连续 ≥2 帧）
```

## 三、每一级做什么、为什么、多少资源

### ① 多尺度 Top-Hat（三尺度并行）

**算法**

```
对每个尺度 s ∈ {5, 9, 15}：
    opened_s = 开运算(原图, s×s)      # 先腐蚀 s×s，再膨胀 s×s
    tophat_s = 原图 − opened_s
输出 = max(tophat_5, tophat_9, tophat_15)
```

**为什么**

经典 Top-Hat 的输出只在“目标尺寸 < 结构元尺寸”时是完整亮块
（Bai & Zhou 2010 证明了结构元与目标尺寸的匹配关系）。
单一尺度必然漏掉一半尺寸范围；多尺度取 max 可以让 **1~14 px** 的目标
都至少在一个尺度上是“完整亮块”。

**代价**

| 项 | 数量 |
|---|---|
| 行缓存 | 3 × 15 行 × 640 × 10 bit = 28.8 KB → **4 块 BRAM** |
| min/max 树 | 3 × (15×15 归约) ≈ **2,000 LUT** |
| 流水线 | 开运算、减法、取 max 各 1 拍 |

---

### ② 局部对比度 LCM（**这一级是核心**）

**算法**

```
以当前像素为中心，取 15×15 窗口，分成 3×3 个 5×5 块：
        ┌───┬───┬───┐
        │ 1 │ 2 │ 3 │
        ├───┼───┼───┤
        │ 4 │ C │ 5 │      C = 中心块 5×5
        ├───┼───┼───┤
        │ 6 │ 7 │ 8 │      1~8 = 八个方向块
        └───┴───┴───┘

  C_mean = 中心块均值
  N_k    = 第 k 块均值（k=1..8）
  LCM    = C_mean / max(N_1..N_8)      # 差比形式，避免除法：C_mean > K · max(N)
```

**为什么（这是解决“左右成对框”和“边缘虚警”的关键）**

| 结构 | C_mean | max(N) | LCM | 判定 |
|---|---|---|---|---|
| **点目标**（无人机）| 高 | 低（八个方向都是背景）| **大** | ✅ 目标 |
| **竖直边缘**（建筑）| 中 | 高（左右两侧有一侧亮）| 小 | ❌ 抑制 |
| **角点** | 中 | 中 | 中 | ⚠️ 需第二判据 |
| **均匀背景** | 低 | 低 | ≈1 | ❌ 抑制 |

**点目标是“八面孤立”的，边缘是“一面相连”的**——这是几何上的本质区别。
现在的 CFAR 完全没有利用这个信息，所以分不开。

**代价**

| 项 | 数量 |
|---|---|
| 行缓存 | 14 行 × 640 × 10 bit = 8.96 KB → **2 块 BRAM** |
| 8 方向块均值 | 8 × 25 输入累加树 ≈ **3,000 LUT** |
| 除法 | 不用除法：`C_mean · 8 > K · ΣN`（ΣN 是 8 块和，1 次乘法）|

> **比现在的 CFAR 31×31 便宜**：CFAR 要 30 行缓存 + 961 输入加法树，
> LCM 只要 14 行 + 8 个 25 输入树。

---

### ③ 双门限

**算法**

```
局部自适应：thr_local = clip(α · LCM_bg, τ_min, τ_max)   # LCM_bg 用 31×31 小窗均值
全局 Top-K：保留 LCM 最大的 K 个像素（K=256）
二值图 = (LCM > thr_local) AND (像素在全局 Top-K 内)
```

**为什么**：只用全局阈值会漏掉暗目标；只用局部阈值会在平坦区放大噪声。
两者取交，既保弱目标又压噪点。

**代价**：Top-K 用 256 级阈值直方图近似 → **约 1,500 LUT + 1 BRAM**

---

### ④ CCL + 形状过滤

**算法**

在二值图上做 8 连通标记（沿用流式并查集），然后对每个连通域算三个判据：

| 判据 | 公式 | 阈值 | 剔除什么 |
|---|---|---|---|
| 面积 | `A = n_pix` | `8 ≤ A ≤ 2047` | 噪点、超大块 |
| **长宽比** | `max(w,h) / min(w,h)` | **≤ 3.0** | **线状结构（建筑边缘、电线）** |
| 填充率 | `A / (w·h)` | ≥ 0.25 | 稀疏的散点噪声 |

**为什么**：LCM 已经压掉了大部分边缘，但残留的斜边缘仍可能通过；
长宽比是最后一道几何闸门。

**代价**：在现有 CCL 上加 w/h 追踪与比较 → **约 500 LUT**

---

### ⑤ 排序输出

按 `score = LCM_peak × √A` 降序，输出前 16 个（`MAX_CAND=16`）。

> 现在的排序只用 peak，会让“又大又弱”和“又小又强”混在一起。

---

### ⑥~⑨ PS / NPU 侧

| 级 | 关键改动 | 理由 |
|---|---|---|
| ⑥ 裁剪 | 边长 `max(48, 4√area)`，上限 128 | 现在固定 96 对大目标不够、对小目标过度放大 |
| ⑦ 分类 | **cls128（0.27 ms）**，不用 yolo11n（28 ms）| 二分类任务用检测网络是浪费 |
| ⑧ 跟踪 | **卡尔曼滤波 + 匈牙利匹配**，不用 EMA | EMA 无法处理遮挡、丢失、交叉 |
| ⑨ 输出 | p≥0.5 **且连续 ≥2 帧**才画绿框 | 单帧置信度不可靠 |

## 四、资源预算

| 级 | LUT | BRAM |
|---|---|---|
| ① 多尺度 Top-Hat | 2,000 | 4 |
| ② LCM | 3,000 | 2 |
| ③ 双门限 | 1,500 | 1 |
| ④ CCL + 形状 | 8,000 | 3 |
| ⑤ 排序 | 2,000 | 1 |
| 接口 / AXI / FIFO | 3,000 | 4 |
| **合计** | **≈19,500** | **15** |

对比现状：自研检测器约 **30,000 LUT**。

**新方案省一半资源，还多了 LCM 判别和形状过滤。**

省下来的 LUT 可以：
- 加第 4 个 Top-Hat 尺度（SE=21，覆盖到 20 px）
- 或者把 CCL 的 `MAX_COMP` 从 64 提到 256

## 五、预期效果（可对照验证）

| 指标 | 现在 | 预期 |
|---|---|---|
| 一个目标的框数 | 1~2（常成对） | **1** |
| 每帧候选数（真实场景）| 5~7（多为杂波）| **1~3** |
| 检测窗口 | 1~4 px | **1~14 px** |
| 建筑边缘虚警 | 高 | **显著下降**（LCM + 长宽比）|
| 纹理背景（草/海）| 恒 0 | 改善（对比度判据不受纹理影响）|

## 六、分阶段实施

| 阶段 | 内容 | 时间 | 可验证点 |
|---|---|---|---|
| **P1** | 加 LCM（③ 前面插一级），保留现有 Top-Hat+CCL | 2h + 15min 编译 | 左右成对框应消失；建筑边缘虚警下降 |
| **P2** | Top-Hat 改多尺度（SE=5/9/15） | 3h + 15min | 6~14px 目标能被检出 |
| **P3** | CCL 加长宽比 + 排序改 `peak×√A` | 1h + 15min | 斜边缘虚警下降 |
| **P4** | PS 侧卡尔曼跟踪 + cls128 分类 | 2h（不用编译）| 框稳定、不闪 |

**P1 是单点收益最大的一步**——它同时解决“左右成对框”和“边缘虚警”两个主要问题。
