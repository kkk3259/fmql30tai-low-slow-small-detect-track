### 3.2 `seq_test.py vs_100.png N` 🔴 **异常**

**⇒ 第一次跑 ×2：**

```
FRAME 0  AR+=3609  RAN  STATUS=0x00760102 n=1
    #0 x=39 y=173 area=21 peak=150
FRAME 1  AR+=3615  RAN  STATUS=0x00770802 n=8     ← 异常
    #0 x=551 y=171 area=21 peak=150
```

**⇒ 第二次跑 ×3（复现）：**

```
FRAME 0  AR+=3609  RAN  STATUS=0x007A0102 n=1
    #0 x=39  y=173 area=21 peak=150
FRAME 1  AR+=3609  RAN  STATUS=0x007B0102 n=1
    #0 x=39  y=173 area=21 peak=150
FRAME 2  AR+=3623  RAN  STATUS=0x007C0802 n=8     ← 异常
    #0 x=551 y=171 area=21 peak=150
```

**⇒ 三个现象同时出现：**

| 现象 | 数值 | 可能原因 |
|---|---|---|
| **n 从 1 跳到 8** | 1 → 8 | 候选表帧间未清零（`docs/35` 第 24 节提过）|
| **x 从 39 跳到 551** | 39 → 551 | 同一批候选的坐标被错位读取 |
| **AR 从 3609 涨到 3615/3623** | +6 / +14 | 多发 6~14 个 AR × 64 字节 ≈ 6~14 行，疑似行请求越界 |

**⇒ 规律：前 2~3 帧正常，之后必现（不是偶发）。**

**⇒ 我的判断：这是 PL 侧问题（候选表清零时序 / AR 计数），我不动 RTL，留给你查。**

### 3.3 `cam3d_test.py --n 6 --npu 0` ✅（**第一次失败**）

**⇒ 第一次直接用默认参数，失败：**

```
[ WARN] global cap_v4l.cpp (902) open VIDEOIO(V4L2:/dev/video0): can't open camera by index
PL3D base=0x1000 VERSION=0x00010000
cap fail
```

**⇒ 原因：`cam3d_test.py` 的 `--cam` 默认值是 0，而当前 USB 相机枚举成 `/dev/video1`**（板载 Linlon VPU 占了 video2；插拔后设备号会变）。

**⇒ 加 `--cam 1` 后通过：**

```
F00 PL=4.2ms st=0x007C0801 n=1
F01 PL=4.2ms st=0x007D0801 n=0
F02 PL=4.2ms st=0x007E0801 n=0
F03 PL=4.2ms st=0x007F0801 n=0
F04 PL=4.2ms st=0x00800801 n=0
F05 PL=4.2ms st=0x00810801 n=0
AVG PL=4.2ms  cand/frame=0.2
```

**⇒ PL 4.2 ms 符合期望（4~5 ms）。后 5 帧 n=0 是因为画面里没有 2~4 px 的小目标。**

**⇒ **建议**：`cam3d_test.py` 也加个 `find_cam()`（我在 `cam3d_pipe.py` 里已加，按 v4l2 名字自动选）。

## 3. A/B/C 三种参数（回传项 3）

| 案例 | 参数 | fps | PL | ncand | 截图 |
|---|---|---|---|---|---|
| **A** | `--gamma 1.0 --color 1` | 16.71 | 4.27 ms | **0** | `snap_A.jpg` 23,587 B |
| **B** | `--gamma 0.08 --color 1` | 15.73 | 4.25 ms | **0** | `snap_B.jpg` 23,968 B |
| **C** | `--gamma 0.08 --invert 1 --color 1` | 16.13 | 4.21 ms | **0** | `snap_C.jpg` 23,811 B |

**⇒ 三张截图的画面几乎一样（平均像素差 3.8~4.9，主要来自场景变化与自动曝光），因为这三种参数只改「送 PL 的那份」，显示的是原图。**

**⇒ 三者的 `ncand` 全部为 0。**

**⇒ 抓图时画面是**显示器 + 桌面**，显示器中央**有 4 个肉眼可见的白点**（就是 `npu_trigger.png` 那张图的 4 个点），但相机拍屏幕后每个点只剩 **1~2 px**，低于 SE=5 的检出下限。**

**⇒ 换句话说：不是 gamma/invert 没生效，是「相机拍屏幕」这个场景本身检不出。**

**⇒ 这也印证了你手册第 7 节第 1 条：SE=5 只能看 2~4 px。**
