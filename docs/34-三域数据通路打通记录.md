# 34 - 三域检测器数据通路打通记录（2026-11-01 凌晨）

## 结论一句话

**三域位流（PS7 + AI_Mate NPU + 我们的检测器）里，检测器已经能正确读到 PL DDR 里的帧像素，
并且产出了候选。** 剩下的是"整帧跑不完"（超时），不是数据错。

## 一、根因链（今晚共 7 层，逐层拆掉）

| # | 症状 | 真因 | 修法 |
|---|---|---|---|
| 1 | 板子加载位流后失联 | 重配 PL 时还有进程持有 PL（`/dev/mem` mmap 或 AXI 事务未完） | `pkill -9` 全部 PL 使用者 → `sleep 3` → 写 firmware → `sleep 3` |
| 2 | `ar` 次数是 8 倍 | 以为一次 AR 只给 8 字节 | 平台一次 AR 给 **512 位 = 64 字节 = 64 个连续像素** |
| 3 | 只吃了 8 个像素 | `lbuf <= {448'b0, lin_data_c[63:0]}` | 改为 `lbuf <= lin_data_c`（整 512 位） |
| 4 | 推 8 字节就收工 | `if (lbcnt == 6'd7)` | 改为 `if (lbcnt == 6'd63)` |
| 5 | AR 地址步进错 | `line_idx << 3`（8 字节） | 改为 `line_idx << 6`（64 字节） |
| 6 | 一个 AR 都不发 | `lin_req_t` 漏复位 → 恒 X → toggle 永不翻转 | 补复位 |
| 7 | 每字节给 `px_pushed` 加 8 | `+ 32'd8` 写在推字节循环里 | 改为 `+ 32'd1` |

第 2~5 条是同一件事的四次误判，**根子是把学长 `adder_top.v` 的 64 位端口
（`.itf_rdata(User_Ddr_rdata)` 从 512 位静默截断成 64 位）当成了"平台只给 64 位"**。
他只用低 32 位是因为加法 demo 只需要几个数，我们照抄就把 7/8 的像素丢了。

## 二、决定性证据

### 1. 仿真（`pl/tb/tb_user_op_line.v`）

```
AR#0 addr=0   AR#1 addr=64   AR#2 addr=128   …        ← 步进 64 字节
PUSHED=3072   请求行=48   AR=48   RV=48   WD=0        ← 48×64 = 3072，不多不少
捕获比对：0 / 256 不一致
VERDICT LINE-OK
```

### 2. 板上（fix12 位流，`ours3d_fix12.bin`）

**重载位流后跑第一帧**（`capdump.py`，渐变图 `px=10+((x+3y)%240)`）：

```
idx : exp  got
  0 :  10   10
  1 :  11   11
  2 :  12   12
  …
 63 :  73   73
前 64 个里有 0 个不一致
最佳线性映射：命中 64/64, got[i] = exp[1*i + 0]
```

逐字节全对、映射是恒等。`STATUS = 0x00000804`（n=8，err=1）。

## 三、一个必须记住的坑

`cap_wd`（像素捕获写指针）只在复位时清零，不随每帧清零。
所以同一个位流连跑两次抓图，第二次看到的是**第一次的残留数据**——
我一度把"全是 40"当成数据通路错误，实际那是上一帧的缓存。

判据：想知道真实首帧，必须重载位流后再跑第一次抓图。

## 四、还没解决的

| 现象 | 数值 | 判断 |
|---|---|---|
| `ar = rv` | 3603 / 3603 | 请求与返回数量对上 |
| `wd`（看门狗） | 924 | 每次 AR 平均等 ~1024 拍才被平台接受 |
| `err` | 1 | 整帧没在检测器的喂数看门狗窗口内跑完 |
| 候选坐标 | `(478,0)(184,17)(424,17)…` 全挤在 y≈0~28 | 帧不完整导致的残帧结果 |

**根因：3603 次 AR × ~1024 拍等待 ≈ 18.5 ms（200 MHz）+ 4.6 ms 推像素 ≈ 23 ms，
贴着 31 ms 的喂数看门狗边界，稍慢一点就超时。**

### 下一步（按性价比排序）

1. 放宽 `ip2_axi_top` 的喂数看门狗（ext 模式）到 100~200 ms —— 一行 RTL，重编 40 分钟
2. **让 AR 流水起来**（inflight 2~4 + 地址 FIFO），把 18.5 ms 压到 5 ms 以内 ——
   但学长说过平台只有一个 AR pending 槽，需先用仿真确认能否多笔并存
3. 顺手把 `cap_wd` 改成每帧清零，避免下次再被残留数据误导

## 六、装载位流的纪律（血泪换来的）

```bash
pkill -9 -f "cam_[p]ipe"; pkill -9 -f "detect3[d]"; pkill -9 -f "still_prob[e]"
sleep 3
echo xxx.bin > /sys/class/fpga_manager/fpga0/firmware
sleep 3
cat /sys/class/fpga_manager/fpga0/state     # 必须是 operating
# 才开始访问寄存器
```

pkill 的模式要带方括号（`cam_[p]ipe`），否则会匹配到自己这条 ssh 命令，把会话杀掉。
